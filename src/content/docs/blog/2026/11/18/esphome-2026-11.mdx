## Short on time? Here's the quick version

This is the short, plain-language version for anyone short on time or still finding their way around ESPHome. The full technical post continues below.

- **Sub-devices:** every entry under `esphome: devices:` now needs a `relation:` field – `via` for a separate physical device reached through this node, `child` for a logical part of this node.
- **HTTP requests in scripts:** `http_request.get`, `.post` and `.send` no longer pause the script, so add `mode: queued` or `mode: parallel` where repeated runs must not be skipped.
- **ESP-IDF minimum version:** if your ESP32 build pins the ESP-IDF framework to a 5.0 version, move it to 5.1 or newer (or remove the pin).

**New features:** ESPHome uses less memory on every supported chip, especially the ESP8266, and the way automations are built now produces smaller, faster code.

**Also in this release:** over thirty new components plus many smaller fixes and improvements.

If you're running a typical config, there's nothing else you need to check before updating – aside from the items above.

For the full release overview and technical detail – including anything that affects custom lambdas, external components or non-standard setups – keep reading below.

## Release overview

{/* RELEASE_OVERVIEW_START */}
ESPHome 2026.11.0 is a framework release. Another large sweep of entity names, filter tables and lookup strings leaves
RAM on ESP8266 and lives in flash on every platform. Scheduler timers lose their string names, cover, fan, valve and
lock traits pack into one byte, and several components switch from heap vectors to fixed buffers. The generated code
for automations now compiles to plain C++ control flow, saving about 1.6 KB of RAM on ESP8266 and ESP32 IDF for a modest
configuration.

Codegen gets a wave of shared helpers, so new components and migrations need less boilerplate: new `Apply` entity
classes for hub-forwarding buttons, switches, numbers and selects, `SUB_*` and `PUBLISH_STATE` macros for child
entities, and byte, I2C, UART, BLE and modbus helpers that roll out across dozens of drivers. The minimum ESP-IDF rises
to 5.1, LibreTiny goes to 1.14.0 with BDK 3.0.78 on Beken chips, and `esp_hosted` moves to 3.0.10. Native ESPHome OTA
now falls back to UDP when the link is lossy, so uploads finish on Wi-Fi that would stall the previous TCP data phase.
`wifi: ap:` with `web_server:` now serves the interface as a captive portal, the DHCP lease is cached across reboots
and Wi-Fi Easy Connect lands on ESP32.

OpenThread on ESP32 gains an experimental border router that bridges Thread to Wi-Fi. nRF52 picks up a crash coredump,
a native toolchain entry, a dongle board, BLE OTA through the Adafruit bootloader and SMP-over-UDP. HTTP requests from
automations no longer block the main loop, the logger buffers early boot lines for later replay over the API, and the
web server stops exposing internal entities over REST. This release also adds over thirty new components, including
Daikin Madoka BLE, USB audio and keyboard, an RTSP server, a VNC client, BLE MIDI, HDMI-CEC and the ESP32 ULP
coprocessor, twelve new climate IR platforms, and many new sensors, radars and expanders. A short codebase-correctness
sweep closes memory, event-decoding and REST-visibility bugs.
{/* RELEASE_OVERVIEW_END */}

## Upgrade checklist

{/* UPGRADE_CHECKLIST_START */}
- If you use `esphome: devices:` for sub-devices, add `relation: via` (separate physical device) or `relation: child`
  (logical part of this node) to every entry.
- If you use OpenThread on ESP32, make sure your build uses ESP-IDF 5.5.5 or newer; remove any pinned
  `esp32.framework.version` older than that.
- If you target the ESP32 with ESP-IDF, remove any pin to ESP-IDF 5.0.x; the minimum is now 5.1.
- If you use `esp32_hosted`, require ESP-IDF 5.5 or newer, add `d1_pin` on a 1-bit SDIO setup, and remove
  `active_high: false` (use the default; `active_high: true` works with a deprecation warning).
- If you use OpenThread on ESP32 without anything else that needs IPv4, add `network: enable_ipv4: true` to keep
  IPv4 on.
- If you use `http_request` actions inside a script, set `mode: queued` or `mode: parallel` where repeated runs must
  not be skipped; actions no longer block the script.
- If you have `clk_mode:` on the `ethernet:` component, move it to the `clk:` block with `mode:` and `pin:`.
- If you have `provider:` on `dlms_meter:`, drop it; for `provider: netznoe` add the two `custom_patterns` from the
  release notes.
- If you have DLMS meter sensors using predefined keys such as `voltage_l1` or `timestamp`, replace each with its
  own entity using `obis_code`.
- If you have `update_on_release:` on an LVGL number, replace it with `trigger: on_release`.
- If you have `dump_device_info:` on `nextion:`, delete it; device info is always logged.
- If you have `platform: qspi_amoled`, change it to `platform: qspi_dbi`.
- If you use `delay`, `wait_until` or `script.wait` inside emonTx `on_json`/`on_data`, MQTT `on_json_message`, or
  Haier `on_status_message`, copy the values you need into globals first and defer from a separate script.
- If you drive internal entities through the web server REST API by URL, add `include_internal: true` under
  `web_server:`.
- If you have NEC `remote_transmitter.transmit_nec` actions with `command_repeats` above 10 or equal to 0, change
  them to a value between 1 and 10.
- If you have `on_nec` lambdas comparing `x.command_repeats`, update them - the value is always 1 now and the check
  no longer works.
- If you have Panasonic IR configs captured from a 56-bit remote, run the dumper again and update `address_2` and
  `command`.
- If you have MagiQuest `on_magiquest` lambdas comparing `x.wand_id` or `x.magnitude`, re-dump and use the new values.
- If you have a `canbus.send` with a constant payload longer than 8 bytes, shorten it to at most 8 bytes.
- If you use `esp32_rmt_led_strip`, `remote_transmitter` or `remote_receiver` with a custom `rmt_symbols` or multiple
  components, re-run validation; conflicts and invalid sizes now fail at config time.
- If you use `color_bwr` e-paper panels (WeAct 3C, Waveshare B, Waveshare BWR, Inkplate 2), expect color mapping to
  change; the test card and lambdas on WeAct 3C or Waveshare 7.5" V2 BWR also change because they now report
  `DISPLAY_TYPE_COLOR`.
- If you use the CB3S board (LN-CB3S V1.0) with the `D12` alias, update your pin to `D13` or `PA11`; `D12` now
  drives PA10.
{/* UPGRADE_CHECKLIST_END */}

## ESP8266 RAM diet and framework-wide flash tables

ESP8266 keeps on a strict RAM budget, and this release shaves another large chunk off it by moving constant tables and
strings into flash. Entity names, device classes, icons, log tags, filter tables, effect lists, enum option lookups
and action payloads now live in flash on every build, and are only copied into RAM when a component actually uses them.
Led by [@bdraco](https://github.com/bdraco), close to a hundred PRs touch this area, across core helpers like
`ConstVector`, `PROGMEM_STRING_TABLE`, `cg.extern_progmem_array` and `ESPHOME_LOG_TAG`, and the component rollouts
that use them.

- **Entity names and icons in flash** - `name:`, `icon:` and device class strings are read straight from flash on
  ESP8266, and the native API sends them straight from flash too ([#20423](https://github.com/esphome/esphome/pull/20423),
  [#21106](https://github.com/esphome/esphome/pull/21106), [#21111](https://github.com/esphome/esphome/pull/21111)).
- **Filter, effect and lookup tables moved to flash** - sensor filter tables, light effect lists, climate presets,
  alarm codes, switch and button payloads, remote IR codes, radar settings and dozens of per-driver lookup tables now
  sit in flash and are shared across instances ([#20071](https://github.com/esphome/esphome/pull/20071),
  [#20074](https://github.com/esphome/esphome/pull/20074), [#20076](https://github.com/esphome/esphome/pull/20076),
  [#20078](https://github.com/esphome/esphome/pull/20078), [#20080](https://github.com/esphome/esphome/pull/20080),
  [#20082](https://github.com/esphome/esphome/pull/20082), [#20083](https://github.com/esphome/esphome/pull/20083),
  [#20204](https://github.com/esphome/esphome/pull/20204), [#20222](https://github.com/esphome/esphome/pull/20222),
  [#20394](https://github.com/esphome/esphome/pull/20394)).
- **Web server strings off RAM** - the remaining ESP8266 web server strings, resource tables and entity domain names
  move to flash ([#20300](https://github.com/esphome/esphome/pull/20300),
  [#21113](https://github.com/esphome/esphome/pull/21113), [#21115](https://github.com/esphome/esphome/pull/21115)).
- **Manual IP settings in flash** - manual Wi-Fi and Ethernet IP settings are stored in flash on ESP8266 too
  ([#21708](https://github.com/esphome/esphome/pull/21708), [#21712](https://github.com/esphome/esphome/pull/21712)).
- **Shared switch lookup tables** - ESP8266 switch lookup tables leave RAM ([#20398](https://github.com/esphome/esphome/pull/20398)).

## Lower RAM for every component instance

RAM savings continue beyond ESP8266. Scheduler timers no longer carry a per-component name string, several trait flag bytes are packed, and the big automation code generation rewrite below shrinks the framework object graph. Numbers below are from the PR measurements against the current release line.

- **Numeric scheduler IDs** - scheduler timers now match components by small integer IDs rather than string literals, so lookups become integer compares. The change rolls through core, climate, select, Tuya, Dallas, Modbus, speaker, Zigbee, voice_assistant and many sensor drivers ([#20361](https://github.com/esphome/esphome/pull/20361), [#20365](https://github.com/esphome/esphome/pull/20365), [#20367](https://github.com/esphome/esphome/pull/20367), [#20368](https://github.com/esphome/esphome/pull/20368), [#20374](https://github.com/esphome/esphome/pull/20374), [#20375](https://github.com/esphome/esphome/pull/20375), [#20376](https://github.com/esphome/esphome/pull/20376), [#20377](https://github.com/esphome/esphome/pull/20377), [#20378](https://github.com/esphome/esphome/pull/20378), [#20380](https://github.com/esphome/esphome/pull/20380), [#20381](https://github.com/esphome/esphome/pull/20381)).
- **Trait flag packing** - [Cover](/components/cover/), [fan](/components/fan/), valve and lock traits pack their boolean flags into single bytes, and `esp32_rmt_led_strip` reshuffles members to fit base class padding ([#21339](https://github.com/esphome/esphome/pull/21339), [#21340](https://github.com/esphome/esphome/pull/21340), [#21343](https://github.com/esphome/esphome/pull/21343), [#21344](https://github.com/esphome/esphome/pull/21344), [#21838](https://github.com/esphome/esphome/pull/21838)).
- **No duplicated storage** - MQTT rebuilds subscription topics on demand instead of storing them, and components such as `bedjet`, `nfc`, `thermopro_ble`, `graph`, `mqtt_subscribe`, `key_collector`, `display_menu_base`, `bme680_bsec` and `tuya` stop copying strings they only read ([#20762](https://github.com/esphome/esphome/pull/20762), [#21204](https://github.com/esphome/esphome/pull/21204), [#21205](https://github.com/esphome/esphome/pull/21205), [#21206](https://github.com/esphome/esphome/pull/21206), [#21207](https://github.com/esphome/esphome/pull/21207), [#21208](https://github.com/esphome/esphome/pull/21208), [#21209](https://github.com/esphome/esphome/pull/21209), [#21210](https://github.com/esphome/esphome/pull/21210), [#21211](https://github.com/esphome/esphome/pull/21211), [#21212](https://github.com/esphome/esphome/pull/21212)).
- **Fixed-size buffers replace heap allocations** - radar components, GPS listeners, speaker pipelines, usb_uart buffers and the Weikai UART driver use fixed-size storage and ring buffers instead of growing heap vectors ([#20379](https://github.com/esphome/esphome/pull/20379), [#21201](https://github.com/esphome/esphome/pull/21201), [#21203](https://github.com/esphome/esphome/pull/21203), [#21347](https://github.com/esphome/esphome/pull/21347), [#21476](https://github.com/esphome/esphome/pull/21476), [#21478](https://github.com/esphome/esphome/pull/21478)).

## Automations compile to C++ control flow

Led by [@clydebarrow](https://github.com/clydebarrow), the code generator for automations has been rebuilt. `if`, `choose`, `while`, `repeat` and runs of simple actions no longer need an action object per step; they compile straight into the generated function as C++ control flow. On a test config with eight automations of three actions each, the stack of changes saves **1632 bytes of RAM** and **1216 bytes of flash** on ESP8266, and **1632 bytes of RAM** and **1628 bytes of flash** on ESP32 IDF. Lambda and `script.execute` chains no longer grow the stack along the way.

- **Adjacent actions merge** - runs of `register_apply_action` and `lambda:` actions become one generated function and one object ([#21978](https://github.com/esphome/esphome/pull/21978)).
- **Inline callback automations run directly** - a trigger whose actions are all inline calls the generated function straight from the callback, with no automation object ([#21979](https://github.com/esphome/esphome/pull/21979)).
- **Control flow turns into C++** - `if`, `choose`, `while` and `repeat` with inline bodies become `if`, `switch`, `while` and `for` in the generated function. The change also fixes a bug where a false condition inside a nested `while` could stop its outer `parallel` script ([#21980](https://github.com/esphome/esphome/pull/21980)).

## Codegen helpers for component authors

A second large framework effort, driven mostly by [@bdraco](https://github.com/bdraco), standardises how components are described in Python. Nine helpers do work that was previously hand-written per component: `new_i2c_component`, `new_uart_component`, `new_spi_component`, `options()` for enum keys, `cg.add_pin`, `cg.add_variable`, `cg.add_optional`, `assign_bits` and `register_parented`. The `SUB_*` macros declare child entities with one line and the `PUBLISH_STATE` macro publishes them with one more, so hub drivers no longer repeat `if (pointer) pointer->publish_state(value)` for each sub-entity. A new [`Apply` entity](https://github.com/esphome/developers.esphome.io/pull/238) family lets a hub forwarding button, switch, number or select ship as a single Python line and no C++ class at all. Component authors can see the new helpers in `AGENTS.md`; these are migration tracks that touch dozens of components and shrink the codebase without changing behaviour.

## ESP-IDF 5.1 floor and library refresh

The minimum ESP-IDF rises to 5.1 and three major vendor libraries are refreshed, so builds stop configuring with deprecated symbols and devices built on them stop hitting the known bugs. [LibreTiny](/components/libretiny/) now defaults to 1.14.0 with Beken BDK 3.0.78 on BK7231N and BK7231T, which fixes WPA3 support on those chips, stops the BK7231T captive portal from losing saved credentials and fixes a watchdog trip during web OTA ([#21531](https://github.com/esphome/esphome/pull/21531)). `esp_hosted` on the ESP32-P4 and Tab5 jumps to 3.0.10, which repairs 1-bit SDIO and no longer erases the co-processor partition at OTA begin ([#21394](https://github.com/esphome/esphome/pull/21394)). `esp-zigbee-sdk` rises to 2.0.5 and `esp-audio-libs` to 4.1.0 ([#20998](https://github.com/esphome/esphome/pull/20998), [#20754](https://github.com/esphome/esphome/pull/20754)). The GCC 12 toolchain that ships with ESP-IDF 5.1 also lets ESPHome drop its 5.0-specific workarounds, so basename debug flags apply everywhere and `CONFIG_SW_COEXIST_ENABLE` is written under its current name ([#21398](https://github.com/esphome/esphome/pull/21398)). `espressif/esp-adf-libs` and `espressif/esp-hosted` binaries are now downloaded and cached rather than carried in the repository ([#20065](https://github.com/esphome/esphome/pull/20065)).

## OTA uploads that finish on bad Wi-Fi

Led by [@bdraco](https://github.com/bdraco), the native ESPHome OTA protocol now falls back to UDP when the TCP handshake shows the link is lossy. The full TCP handshake still runs first, and the data phase moves to UDP only when it is worth it; everything stays encrypted when Noise is configured. On an ESP32 next to the laptop, a clean upload takes 13 to 16 seconds on UDP against 36 to 70 seconds on TCP, and an upload with 65% loss added finishes in just over three minutes where TCP fails every time ([#20498](https://github.com/esphome/esphome/pull/20498)). The companion client adds a few patience changes to match: handshake timeouts rise from 20 to 60 seconds, up to five attempts for a first connection and nine once the device is reached, so a slow Wi-Fi recovery no longer gives up early. `--prompt-ota-key` and `old_key` options let an upload retry with a fresh or previous OTA key when the device has already moved on ([#19397](https://github.com/esphome/esphome/pull/19397), [#19398](https://github.com/esphome/esphome/pull/19398)).

## OpenThread border router on ESP32

Led by [@pputerla](https://github.com/pputerla), the [`openthread`](/components/openthread/#openthread-border-router) component gains an ESP32 border router mode. An ESP32-C5 or C6 bridges its native 802.15.4 radio to Wi-Fi, and the other Wi-Fi ESP32 variants bridge an external radio co-processor over UART. Thread starts at boot, border routing starts once Wi-Fi has an address, and the SDK is driven from a single OpenThread task under one lock so clean reboots work. OpenThread on ESP32 now needs ESP-IDF 5.5.5 or newer, which has been the default for a few releases ([#18104](https://github.com/esphome/esphome/pull/18104)). The feature is marked experimental: the native radio ran for two weeks without a restart in testing, while the external RCP mode hung occasionally during a three-week soak.

## Non-blocking HTTP requests and boot log replay

Two automation-side features let devices do more work in the background. [@clydebarrow](https://github.com/clydebarrow) reworked `http_request.get`, `.post` and `.send` into asynchronous actions driven by the component's `loop()`. On an ESP32-S3, the main loop stall for a plain HTTPS GET drops from 2.4 to 3.6 seconds to about 0.3 seconds, and for a 70 KB LAN download from 3.6 seconds to tens of milliseconds. Up to four extra requests queue, so overlapping triggers no longer run back to back. A script containing one of these actions is still running while the request is in flight, so a `mode: single` script that used to fit inside `execute()` now has to use `mode: queued` or `mode: parallel` when it needs to overlap ([#21486](https://github.com/esphome/esphome/pull/21486)). A per-request `timeout:` option lands in the same area ([#20821](https://github.com/esphome/esphome/pull/20821)).

The [logger](/components/logger/) also gains an optional `boot_log_buffer_size:` and a matching `logger.replay_boot_logs:` action. Lines captured from the moment the logger starts are replayed over the native API when the first client connects, so a warning that fired before Wi-Fi came up is still visible later ([#17666](https://github.com/esphome/esphome/pull/17666)). The buffer is a compile-time member, nothing allocates on the heap, and the option compiles out entirely when unset. `boot_log_level:` and per-tag `boot_logs:` tune what is kept, and dropped lines are counted so the summary says how much was lost.

## Other notable features

- **[Switch initial state](/components/switch/)** - `initial_state:` and `restore_state:` work with flash or RTC storage for platforms whose switches do not have their own restore ([#20978](https://github.com/esphome/esphome/pull/20978)).
- **[Light initial effect](/components/light/)** - `initial_state:` can now name an `effect:`, so a strip boots into its startup animation ([#18795](https://github.com/esphome/esphome/pull/18795)).
- **Globals in RTC memory** - a persistent `global` can live in RTC RAM instead of flash, preserved across deep sleep without wearing out the flash ([#13954](https://github.com/esphome/esphome/pull/13954)).
- **[Addressable light power estimation](/components/light/#addressable-light-power-estimation)** - LED strips can report the estimated current draw and limit it on the fly ([#15348](https://github.com/esphome/esphome/pull/15348)).
- **Sendspin as a source** - the [`sendspin`](/components/sendspin/#source) speaker protocol gains a source role, so a device can stream a microphone to a Music Assistant server ([#21696](https://github.com/esphome/esphome/pull/21696)).
- **[`i2s_audio` full duplex](/components/i2s_audio/#full-duplex)** - single-chip speakers and microphones can share one bus ([#19959](https://github.com/esphome/esphome/pull/19959)).
- **ESP32 OTA security** - new `signed_ota_verification` and NVS encryption options in the [`esp32`](/components/esp32/#security) block prepare devices for stronger OTA signing ([#17562](https://github.com/esphome/esphome/pull/17562)).
- **[MQTT over WebSocket](/components/mqtt/#mqtt-over-websocket)** - WebSocket transport on ESP32 IDF and TLS option expansion ([#14318](https://github.com/esphome/esphome/pull/14318), [#16056](https://github.com/esphome/esphome/pull/16056)), plus MQTT session persistence and a crash reporting channel ([#12426](https://github.com/esphome/esphome/pull/12426), [#17935](https://github.com/esphome/esphome/pull/17935)).
- **[Online image progressive decode](/components/image/online_image/)** - decode a JPEG as it downloads, with download start and progress triggers ([#21342](https://github.com/esphome/esphome/pull/21342), [#21355](https://github.com/esphome/esphome/pull/21355)).
- **Runtime image speed-ups** by [@clydebarrow](https://github.com/clydebarrow) - JPEG decoding writes opaque RGB565 frames straight into the buffer, uses integer maths for grayscale and resize, and decodes at the smallest JPEGDEC scale that fits ([#19454](https://github.com/esphome/esphome/pull/19454), [#21386](https://github.com/esphome/esphome/pull/21386), [#21387](https://github.com/esphome/esphome/pull/21387), [#21390](https://github.com/esphome/esphome/pull/21390), [#21393](https://github.com/esphome/esphome/pull/21393), [#21784](https://github.com/esphome/esphome/pull/21784)).
- **ESP32 RMT seat check** - ESPHome checks at compile time that every `esp32_rmt_led_strip`, `remote_transmitter` and `remote_receiver` fits the chip's RMT channels together, so a second strip no longer silently fails to start at boot ([#22172](https://github.com/esphome/esphome/pull/22172)).

## Codebase correctness

Alongside the memory and codegen work, this cycle closes several real correctness gaps.

- **Deferring actions rejected where they would read freed memory** - [`emontx`](https://github.com/esphome/esphome/pull/20516), [`mqtt` `on_json_message`](https://github.com/esphome/esphome/pull/20538) and [`haier` `on_status_message`](https://github.com/esphome/esphome/pull/20539) now reject automations that contain `delay`, `wait_until` or `script.wait`. The received frame is only valid while the automation runs, so a deferring action used to read freed memory at runtime; configs now fail validation with a message pointing at the fix.
- **`esp32_hosted` co-processor update** - updates size their OTA chunks from the host's per-RPC limit, so the previous fixed 1500-byte chunk no longer fails every co-processor update ([#21394](https://github.com/esphome/esphome/pull/21394)).
- **[`libretiny`](/components/libretiny/) crash reports** - BK7238, BK7231N, LN882H and RTL8710B report the previous boot's crash on reboot, following the ESP32 and ESP8266 crash handlers ([#21007](https://github.com/esphome/esphome/pull/21007), [#21012](https://github.com/esphome/esphome/pull/21012), [#21648](https://github.com/esphome/esphome/pull/21648), [#21728](https://github.com/esphome/esphome/pull/21728), [#21752](https://github.com/esphome/esphome/pull/21752)).
- **Remote protocol frame boundaries** - NEC `command_repeats` now sends real NEC repeat frames, MagiQuest reads the full 56 bit frame and checks its checksum, and 56 bit Panasonic frames are decoded in full ([#17663](https://github.com/esphome/esphome/pull/17663), [#10622](https://github.com/esphome/esphome/pull/10622), [#20260](https://github.com/esphome/esphome/pull/20260)).
- **Web server numbers without state** - a number that has not published a state yet is reported as unknown instead of `0`, so the web UI matches what Home Assistant already shows ([#20973](https://github.com/esphome/esphome/pull/20973)).
- **`web_server` internal entities** - the REST endpoints match the page and the API: an internal entity is no longer reachable by a guessed URL unless `include_internal: true` is set ([#20883](https://github.com/esphome/esphome/pull/20883)).

## Breaking changes

{/* BREAKING_CHANGES_USERS_START */}
### Component changes

- **MagiQuest**: The decoder now reads the full 56-bit frame and checks its checksum, so `x.wand_id` and `x.magnitude`
  in `on_magiquest` lambdas change. Old binary sensor matches still work; run the dumper again for lambda values.
  [#10622](https://github.com/esphome/esphome/pull/10622)
- **NEC remote**: `command_repeats` now sends real NEC repeat frames and is clamped to 1 to 10. Received
  `x.command_repeats` is always 1; detect a held button from the frame cadence.
  [#17663](https://github.com/esphome/esphome/pull/17663)
- **Panasonic remote**: Frames of 56 bits or more now decode as `nbits: 56` with the new `address_2` byte. Update
  configs captured from 56-bit remotes with a fresh dump.
  [#20260](https://github.com/esphome/esphome/pull/20260)
- **CAN bus**: A constant `canbus.send` payload longer than 8 bytes now fails validation instead of being silently
  truncated. Fix also stops sending the wrong length for lambda payloads of 256 bytes or more.
  [#20309](https://github.com/esphome/esphome/pull/20309)
- **Ethernet**: Removed the deprecated `clk_mode` option. Use the `clk:` block with `mode:` and `pin:`.
  [#20384](https://github.com/esphome/esphome/pull/20384)
- **DLMS meter**: Removed the deprecated `provider` option. Most configs can drop the key; `provider: netznoe` users
  add the two `custom_patterns` it used to inject.
  [#20385](https://github.com/esphome/esphome/pull/20385)
- **DLMS meter**: Removed the deprecated predefined sensor and text_sensor keys such as `voltage_l1` and `timestamp`.
  Each value is now its own entity with `obis_code`.
  [#20386](https://github.com/esphome/esphome/pull/20386)
- **LVGL**: Removed the deprecated number `update_on_release` option. Use `trigger: on_release`.
  [#20387](https://github.com/esphome/esphome/pull/20387)
- **Nextion**: Removed the deprecated `dump_device_info` option. Device info is always logged; delete the key.
  [#20388](https://github.com/esphome/esphome/pull/20388)
- **QSPI AMOLED**: Removed the legacy renamed component stub. Use `platform: qspi_dbi`.
  [#20396](https://github.com/esphome/esphome/pull/20396)
- **emonTx**: `on_json` and `on_data` reject deferring actions (`delay`, `wait_until`, `script.wait`) at validation.
  Copy the values you need into globals first, then defer from a separate script. `data` and `raw_json` are now
  `StringRef` instead of `std::string`.
  [#20516](https://github.com/esphome/esphome/pull/20516)
- **MQTT**: `on_json_message` rejects deferring actions at validation. Copy the values you need into globals first,
  then defer from a separate script.
  [#20538](https://github.com/esphome/esphome/pull/20538)
- **Haier**: `on_status_message` rejects deferring actions at validation. Copy the values you need into globals
  first, then defer from a separate script.
  [#20539](https://github.com/esphome/esphome/pull/20539)
- **Web server**: REST endpoints no longer match `internal` entities by URL unless `include_internal: true` is set.
  This matches the native API and MQTT behaviour.
  [#20883](https://github.com/esphome/esphome/pull/20883)
- **Web server**: A number entity that has not published a state yet is now reported as unknown instead of `0`. In
  the REST and event-stream JSON it is sent as `"state":"NA","value":"NaN"`.
  [#20973](https://github.com/esphome/esphome/pull/20973)
- **E-paper SPI**: Refactored `color_bwr` handling; WeAct 3C, Waveshare B, Waveshare BWR and Inkplate 2 panels now
  map colors to the nearest of black, white or red in RGB space. Waveshare 7.5" V2 BWR and WeAct 3C panels now
  report `DISPLAY_TYPE_COLOR` instead of `BINARY`, so the test card and `get_display_type()` lambdas change.
  [#19654](https://github.com/esphome/esphome/pull/19654)
- **HTTP request**: `http_request.get`, `post` and `send` actions are now asynchronous and run from the component
  loop. Scripts containing these actions keep running until the response arrives; set `mode: queued` or
  `mode: parallel` where repeated runs must not be skipped. New `max_concurrent_requests` option (1 to 4) allows more
  than one request in flight.
  [#21486](https://github.com/esphome/esphome/pull/21486)
- **API sub-devices**: `relation:` is now required on every entry under `esphome: devices:`. Add `relation: via` to
  keep today's behaviour for a physical device reached through this node, or `relation: child` for a logical part of
  this node.
  [#21232](https://github.com/esphome/esphome/pull/21232)

### Platform changes

- **Network**: Added `network: enable_ipv4` (default `true`). An `openthread` config on `esp32` without anything
  else requiring IPv4 now defaults IPv4 off; add `network: enable_ipv4: true` to opt back in. `enable_ipv6` now
  resolves automatically when a component requires it, so `openthread` no longer needs `enable_ipv6: true`.
  [#14526](https://github.com/esphome/esphome/pull/14526)
- **OpenThread**: Added Border Router support on ESP32. Requires ESP-IDF 5.5.5 or newer, for plain Thread devices as
  well as border routers. Remove a pinned `esp32.framework.version` or raise it to 5.5.5.
  [#18104](https://github.com/esphome/esphome/pull/18104)
- **esp32_hosted**: Moved to `esp_hosted` 3.0.10. Requires ESP-IDF 5.5 or newer. A 1-bit SDIO setup must now set
  `d1_pin` (the pin wired to DAT1). `active_high: false` is no longer accepted; `active_high: true` works with a
  deprecation warning.
  [#21394](https://github.com/esphome/esphome/pull/21394)
- **ESP32**: Minimum ESP-IDF version is now 5.1. A build pinned to 5.0.x fails validation.
  [#21398](https://github.com/esphome/esphome/pull/21398)
- **LibreTiny**: Bumped to 1.14.0 with BK7231N and BK7231T built on Beken BDK 3.0.78. Fixes STA+AP captive portal
  credential saving, OTA watchdog resets and Wi-Fi-less reboot loops. LN-CB3S V1.0 configs that use the `D12` alias
  now drive PA10 instead of PA11; the old pin is `D13` or `PA11`. ADC readings on BK7231N and BK7231T are now
  correct (they previously read about half the true voltage).
  [#21531](https://github.com/esphome/esphome/pull/21531)
- **ESP32 RMT**: ESPHome now checks at validation that `esp32_rmt_led_strip`, `remote_transmitter` and
  `remote_receiver` fit the chip's RMT channels together. Configs with too many components, with more than one
  `use_dma` in a direction, or with an invalid `rmt_symbols` value now fail validation instead of failing at boot.
  [#22172](https://github.com/esphome/esphome/pull/22172)

### Undocumented API changes

{/* UNDOCUMENTED_API_CHANGES_START */}
Many components reorganized internal C++ APIs this release. These changes are not covered by the formal breaking
change policy, but lambda users and external component maintainers may need to adjust. Grouped by theme:

### Entity names and strings moved to flash

- **EntityBase names**: `EntityBase::name_` is now a `ProgmemStringRef` on ESP8266. `get_name()` is deprecated and
  returns a `const StringRef &` with a RAM copy made on first use (removal in 2027.5.0). Use `get_log_name()` for log
  lines and `get_name_to(buffer)` or `name_equals(other)` where you need the value.
  ```cpp
  // Before
  ESP_LOGD(TAG, "'%s' updated", this->name_.c_str());

  // After
  ESP_LOGD(TAG, "'%s' updated", LOG_STR_ARG(this->get_log_name()));
  ```
  [#20423](https://github.com/esphome/esphome/pull/20423)
  [#20615](https://github.com/esphome/esphome/pull/20615)

- **API action strings**: The `(progmem)` proto option now also applies to string fields.
  `HomeassistantActionRequest.service` and `HomeassistantServiceMap.key`/`value` carry `ProgmemStringRef` values.
  Code that fills a `HomeassistantActionRequest` assigns `ProgmemStringRef`, for example
  `resp.service = ProgmemStringRef(StringRef(name));`.
  [#20425](https://github.com/esphome/esphome/pull/20425)

### Component names and payloads kept in fixed buffers or StringRef

- **BedJet**: `BedJetHub::get_name()` now returns `const char *` from a fixed 24-byte buffer instead of
  `std::string`. Pass it directly to `%s` log arguments.
  [#21204](https://github.com/esphome/esphome/pull/21204)

- **NFC binary sensor**: `set_ndef_match_string()` / `set_tag_name()` now take `const char *`. `match_string_` is
  stored as a `StringRef`.
  [#21208](https://github.com/esphome/esphome/pull/21208)

- **key_collector**: The five key lists (`start_keys`, `end_keys`, `back_keys`, `clear_keys`, `allowed_keys`) are
  stored as `StringRef` views of the YAML literals; the setters take `const char *`.
  [#21210](https://github.com/esphome/esphome/pull/21210)

- **graph**: `GraphTrace::get_name()` now returns `StringRef` instead of `std::string`. Lambdas comparing with `==`,
  calling `.c_str()`, or assigning to `std::string` keep working.
  [#21211](https://github.com/esphome/esphome/pull/21211)

### Flash tables for internal lookup strings

- **Haier**: The hOn alarm message table (`HON_ALARM_MESSAGES`, `HON_ALARM_COUNT`) is removed from `hon_packet.h`
  and kept as a `PROGMEM_STRING_TABLE`. On ESP8266, the `message` passed to `on_alarm_start` / `on_alarm_end` is a
  static buffer overwritten by the next alarm change; use `code` instead if an automation waits.
  [#20641](https://github.com/esphome/esphome/pull/20641)

- **Nextion**: `get_queue_type_string()` is no longer virtual and returns `const LogString *` instead of
  `const char *`. Wrap with `LOG_STR_ARG()` to pass it to `%s` log arguments.
  [#20658](https://github.com/esphome/esphome/pull/20658)

- **NFC URI prefixes**: `PAYLOAD_IDENTIFIERS` and `PAYLOAD_IDENTIFIERS_COUNT` are removed from `ndef_record_uri.h`.
  The table is now a `PROGMEM_STRING_TABLE` in `ndef_record_uri.cpp`.
  [#20709](https://github.com/esphome/esphome/pull/20709)

### Hub forwarding entities (Apply pattern)

Many hub components replaced their per-entity C++ classes with codegen-only `Apply*` entities. The hub gains a
public method that takes the state, index or value. External code that inherited from the removed classes should
switch to `ApplyButton` / `ApplyNumber` / `ApplySelect` / `ApplySwitch` / `ApplyFloatOutput` / `ApplyBinaryOutput`.
The generated entity's auto-generated id changes; entity names and object ids do not.

- **Hub buttons**: ld2410, ld2412, ld2420, ld2450, seeed_mr24hpc1, seeed_mr60fda2, haier, hoermann_hcp,
  dfrobot_sen0609, bq25186, espectre, tfluna.
  [#20964](https://github.com/esphome/esphome/pull/20964)

- **Hub numbers**: ld2410, ld2412, ld2450, seeed_mr24hpc1, dfrobot_sen0609. `set_gate_threshold` on ld2410 now takes
  the number entity itself.
  [#20965](https://github.com/esphome/esphome/pull/20965)

- **Hub selects**: ld2410, ld2412, ld2420, ld2450, seeed_mr24hpc1, seeed_mr60fda2, haier, es8388, espectre.
  [#20966](https://github.com/esphome/esphome/pull/20966)

- **Hub switches**: ld2410, ld2412, ld2450, seeed_mr24hpc1, at581x.
  [#20967](https://github.com/esphome/esphome/pull/20967)

- **Hub channel outputs**: tlc59208f, dac7678, gp8403, my9231, sm2135, sm2235, sm2335, bp1658cj, lp5562, mcp4728,
  pca9685, sm16716, tlc5947, tlc5971, tm1638, bh1745, emc2101, waveshare_io_ch32v003. The hubs gain
  `write_channel(channel, state)` instead of per-channel classes.
  [#21257](https://github.com/esphome/esphome/pull/21257)

- **pipsolar**: `PipsolarSwitch` class removed; switches use Apply entities. `Pipsolar::queue_command` now takes
  `const char *` (a `std::string` overload remains for lambdas).
  [#21659](https://github.com/esphome/esphome/pull/21659)

- **sendspin**: `SendspinEnabledSwitch` class removed.
  [#21673](https://github.com/esphome/esphome/pull/21673)

- **bq25186**: `BQ25186PgGpoSwitch` class removed; the generated code uses `publish="on_success"`.
  [#21675](https://github.com/esphome/esphome/pull/21675)

- **pcm5122**: `PCM5122PowerSwitch` class removed; the generated body calls `set_standby(state)` or
  `set_powerdown(state)` directly.
  [#21677](https://github.com/esphome/esphome/pull/21677)

- **mitsubishi_cn105**: `MitsubishiCN105VerticalVaneDirectionSelect` replaced with `select::ApplySelect`. Both vane
  direction selects now live in one `select:` entry per hub. `WideVaneMode` enumerators renamed from `FAR_LEFT` to
  `POSITION_1` etc.
  [#21863](https://github.com/esphome/esphome/pull/21863)

### Copy / follow entity platforms

- **copy, switch, number, text**: `copy::CopySensor`, `copy::CopyTextSensor`, `switch_::SwitchBinarySensor`,
  `number::NumberSensor` and `text::TextTextSensor` are removed. The entities are now plain `sensor::Sensor`,
  `binary_sensor::BinarySensor` and `text_sensor::TextSensor` that follow a source through a callback registered
  before `setup()`. `setup_priority` is no longer accepted on these entities.
  [#21610](https://github.com/esphome/esphome/pull/21610)
  [#21612](https://github.com/esphome/esphome/pull/21612)

### Remote transmitter actions

- **Per-protocol action classes removed**: `NECAction`, `SonyAction`, `PanasonicAction`, `KeeloqAction`,
  `MagiQuestAction`, `HaierAction`, `MideaAction`, `MirageAction`, `AEHAAction`, `ABBWelcomeAction`, `ProntoAction`,
  `RC6Action` and 20+ others. Codegen now produces stateless functions through `register_protocol_action`.
  External protocols still work through the unchanged Python `register_action`.
  [#20549](https://github.com/esphome/esphome/pull/20549)
  [#20564](https://github.com/esphome/esphome/pull/20564)
  [#20568](https://github.com/esphome/esphome/pull/20568)

- **Byte payload actions**: `uart.write`, `udp.write`, `sx127x`, `sx126x` and `cc1101` send-packet actions use
  `ApplyBytes` instead of per-component `TEMPLATABLE_BYTES` action classes. `SendPacketAction`, `UDPWriteAction`
  and `UARTWriteAction` are removed.
  [#21263](https://github.com/esphome/esphome/pull/21263)

- **UART switch and button payloads**: Payload setters now take a pointer and a length. The vector and initializer
  list overloads used by codegen are removed.
  [#20082](https://github.com/esphome/esphome/pull/20082)

### Triggers built from callbacks

- **display `on_page_change`**: `DisplayOnPageChangeTrigger` is removed and `Display::add_on_page_change_trigger`
  no longer exists. The storage is compiled out when no `on_page_change` is configured. The generated
  `trigger_id` key is gone.
  [#20456](https://github.com/esphome/esphome/pull/20456)

- **graphical_display_menu `on_redraw`**: `GraphicalDisplayMenuOnRedrawTrigger` removed.
  `add_on_redraw_callback()` now passes `const GraphicalDisplayMenu *`.
  [#20452](https://github.com/esphome/esphome/pull/20452)

- **Callback automations with inline actions**: When every action in a callback automation is inline, no
  `Automation` or action object is generated. `ScriptExecuteAction` and `Script::execute_tuple` are removed; use
  `script.execute` through the apply path.
  [#21979](https://github.com/esphome/esphome/pull/21979)

### Numeric scheduler ids and heap-free command queues

- **dallas_temp / one_wire**: `OneWireDevice::get_address_name()` is removed. Format the address with
  `format_hex_prefixed_to(buf, this->address_)` for log lines; `LOG_ONE_WIRE_DEVICE` still works.
  ```cpp
  // Before
  this->set_timeout(this->get_address_name().c_str(), 750, [this] { ... });

  // After
  static constexpr uint32_t CONVERSION_TIMEOUT_ID = 0;
  this->set_timeout(CONVERSION_TIMEOUT_ID, 750, [this] { ... });
  ```
  [#20361](https://github.com/esphome/esphome/pull/20361)

- **dfrobot_sen0395**: The `Command` class hierarchy and `enqueue(std::unique_ptr<Command>)` are gone; commands are
  now 2-byte values in a `StaticRingBuffer`. The documented `dfrobot_sen0395.reset` and `dfrobot_sen0395.settings`
  actions and the switches are unchanged.
  [#20906](https://github.com/esphome/esphome/pull/20906)

### Other API changes

- **Light HSV on addressable strips**: `ESPColorSettable::set_hsv()` now also clears the white channel. A lambda
  that relied on a previous white value being kept must set it explicitly after `set_hsv()`.
  [#20265](https://github.com/esphome/esphome/pull/20265)

- **AddressableLight refactor**: `ESPColorView` and related types were refactored.
  `ESPColorSettable::set(ESPHSVColor)` and `ESPColorRange::set(ESPHSVColor)` are deprecated; use `set_hsv()`.
  External `AddressableLight` subclasses need small changes - see
  [the developer blog post](https://developers.esphome.io/blog/2026/11/18/addressable-light-now-backed-by-a-color-accessor/).
  [#21577](https://github.com/esphome/esphome/pull/21577)

- **I2C little-endian helpers**: 36 sensor components now use the shared `read_byte_16_le`, `write_byte_16_le`,
  `read_bytes_16_le`, `encode_value_le<>` helpers. External components can follow suit; see the helper PR
  [#20938](https://github.com/esphome/esphome/pull/20938).
  [#20939](https://github.com/esphome/esphome/pull/20939)

- **heatpumpir**: `set_protocol()` is gone. The climate is constructed with a `ProtocolTag<P>` so only the
  configured protocol's class is linked.
  [#20707](https://github.com/esphome/esphome/pull/20707)

- **atm90e32**: The public `using_saved_calibrations_` field, the `OffsetRestoreState` type,
  `resolve_offset_restore_state` and `prepare_offset_rollback` helpers are removed. Gain, offset and power offset
  calibration share one save/rollback path.
  [#18731](https://github.com/esphome/esphome/pull/18731)

- **ld6002b / ld600x**: `LD6002BComponent` is now a thin subclass of `ld600x::LD600XComponent`. The twelve
  per-axis area sensor setters collapse into `set_area_sensor(kind, area, axis, sensor)`.
  [#19837](https://github.com/esphome/esphome/pull/19837)

- **pulse_counter**: The software interrupt is now attached to the counted edges only when `internal_filter: 0us`.
  Edge mode setters log an error and ignore a change made after `setup()`.
  [#21271](https://github.com/esphome/esphome/pull/21271)

- **micro_wake_word**: Internal RAM placement is now opt-in through `prefer_internal_ram: true`; disabled models
  release their arena and weight copy.
  [#20529](https://github.com/esphome/esphome/pull/20529)

- **speaker**: `AudioPipeline::start_url()` and `start_file()` take an optional announcement boolean. Existing
  one-argument calls remain valid. Announcements start once the raw buffer has not changed for 1.5 s, in addition
  to the normal startup threshold.
  [#21091](https://github.com/esphome/esphome/pull/21091)

### Breaking changes for developers

{/* BREAKING_CHANGES_DEVELOPERS_START */}
- **Entity names in flash on ESP8266**: `EntityBase::name_` is now a `ProgmemStringRef`. Its `c_str()` is deprecated
  and `get_name()` is deprecated; use `get_log_name()` with `LOG_STR_ARG()` for log calls and `get_name_to(buffer)`
  or `name_equals()` where you need the value. Removal in 2027.5.0.
  [#20423](https://github.com/esphome/esphome/pull/20423)
  [#20615](https://github.com/esphome/esphome/pull/20615)
- **API action strings**: `(progmem)` proto option now applies to string fields. `HomeassistantActionRequest.service`
  and `HomeassistantServiceMap.key`/`value` take a `ProgmemStringRef`. The 384 byte user-action text limit is gone.
  [#20425](https://github.com/esphome/esphome/pull/20425)
- **ESPColorView refactor**: `AddressableLight` and related types were refactored. `ESPColorSettable::set(ESPHSVColor)`
  and `ESPColorRange::set(ESPHSVColor)` are deprecated; use `set_hsv()`. External `AddressableLight` subclasses need
  small changes - see the developer blog post.
  [#21577](https://github.com/esphome/esphome/pull/21577)
- **AddressableLight HSV**: `ESPColorSettable::set_hsv()` now clears the white channel.
  [#20265](https://github.com/esphome/esphome/pull/20265)
- **Display color order**: `draw_pixels_at()` and `ColorUtil` no longer take a color order argument; RGB 888 pixel
  blocks are always `b, g, r` in memory.
  [#20884](https://github.com/esphome/esphome/pull/20884)
- **InternalGPIOPin**: Now binds to the platform pin class instead of a virtual base.
  [#20455](https://github.com/esphome/esphome/pull/20455)
- **RingBuffer alias**: Removed the deprecated `esphome::RingBuffer` alias.
  [#20390](https://github.com/esphome/esphome/pull/20390)
- **alloc_helpers.h**: `helpers.h` no longer re-exports `alloc_helpers.h`; include it directly.
  [#20389](https://github.com/esphome/esphome/pull/20389)
- **Numeric scheduler ids**: Many components moved from string scheduler ids to numeric ids. External components
  using `set_timeout()`/`set_interval()` with strings should migrate to `constexpr uint32_t` ids.
  [#20361](https://github.com/esphome/esphome/pull/20361)
- **Component DOMAIN constants**: Every component now has a `DOMAIN` constant used instead of name literals in code
  generation.
- **LVGL 9.6.0**: Internal LVGL bump may affect external components calling LVGL APIs directly.
  [#20257](https://github.com/esphome/esphome/pull/20257)
- **Light effect list**: Light effect list is kept in a flash `ConstVector`.
  [#20204](https://github.com/esphome/esphome/pull/20204)
- **Climate/Fan traits**: `custom_fan_modes`, `custom_presets` and `preset_modes` are kept in `ConstVector`;
  deprecated traits setters removed.
  [#20213](https://github.com/esphome/esphome/pull/20213)
  [#20214](https://github.com/esphome/esphome/pull/20214)
- **Event types**: Kept in a shared flash table.
  [#20217](https://github.com/esphome/esphome/pull/20217)
- **BedJet/Xiaomi**: `BedJetHub::get_name()` returns `const char *` instead of `std::string`.
  [#21204](https://github.com/esphome/esphome/pull/21204)
  Xiaomi sensors share a new `XiaomiDevice` base.
  [#21483](https://github.com/esphome/esphome/pull/21483)
- **Remote transmitter actions**: Per-protocol `...Action` C++ classes (NECAction, PanasonicAction,
  HaierAction, MideaAction and many more) removed; codegen now produces stateless functions through
  `register_protocol_action`.
  [#20549](https://github.com/esphome/esphome/pull/20549)
  [#20564](https://github.com/esphome/esphome/pull/20564)
  [#20568](https://github.com/esphome/esphome/pull/20568)
- **Remote dumpers**: Stateless dumpers kept in flash.
  [#21563](https://github.com/esphome/esphome/pull/21563)
- **Callback automations**: `build_callback_automation` / `build_trigger_callback` now run directly without
  `Automation` or action objects when every action is inline. `ScriptExecuteAction` and `Script::execute_tuple`
  are removed; use `script.execute` through the apply path.
  [#21979](https://github.com/esphome/esphome/pull/21979)
- **ApplyEntity helpers**: Many hub buttons, numbers, selects, switches and outputs moved to codegen-only `Apply*`
  entities. Per-component entity classes such as `PipsolarSwitch`, `PCM5122PowerSwitch`, `TLC59208FChannel`,
  `BQ25186PgGpoSwitch` are removed; the hubs gain public methods that take the state or channel.
  [#20964](https://github.com/esphome/esphome/pull/20964)
  [#20965](https://github.com/esphome/esphome/pull/20965)
  [#20966](https://github.com/esphome/esphome/pull/20966)
  [#20967](https://github.com/esphome/esphome/pull/20967)
  [#21257](https://github.com/esphome/esphome/pull/21257)
- **Copy entity platforms**: `copy::CopySensor`, `copy::CopyTextSensor`, `switch_::SwitchBinarySensor`,
  `number::NumberSensor` and `text::TextTextSensor` are removed; entities are now plain base-class entities with a
  follow callback.
  [#21610](https://github.com/esphome/esphome/pull/21610)
  [#21612](https://github.com/esphome/esphome/pull/21612)
- **Weikai**: Base classes marked `final`.
  [#17292](https://github.com/esphome/esphome/pull/17292)

For detailed migration guides and API documentation, see the
[ESPHome Developers Documentation](https://developers.esphome.io/).
