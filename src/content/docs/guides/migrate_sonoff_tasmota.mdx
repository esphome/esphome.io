Migrating from previous Tasmota setups is very easy. You just need to have
ESPHome create a binary for you and then upload that in the Tasmota web interface.

> [!CAUTION]
When migrating via OTA on ESP32, from Tasmota v12 or higher (with safeboot partition) it is required to add the
option `allow_partition_access: true` to your config on the first ESPHome firmware you upload to the device.
Failing to do so will soft-brick your device by making OTA updates impossible!

## Writing a configuration

First create a configuration for your device.

Make sure it contains at least the following components: `esp8266` or `esp32`, `esphome`, `logger`, `api`, `ota` and `wifi`. 

For OTA migration of ESP32 devices with Tasmota v12 or higher:
- Remove all other components to make sure the size of the firmware image is `851968 bytes` or less. This will make the migration to the ESPHome partition table easier without requiring any intermediate steps. Check the size of the image after compiling.
- Make sure the WiFi credentials are correct if you removed the `captive_portal` component.
- Make sure to add `allow_partition_access: true` to the ota section of the config:

```yaml
# ESP32 only
ota:
  - platform: esphome
    allow_partition_access: true
```

- Check the version of Tasmota on your device, it tells you which type of ESP32 you have. It is usually displayed at the bottom right.
  - `solo1` -> Single-core ESP32
  - `tasmota32` -> Dual-core ESP32
  - `tasmota32xx` -> Different ESP32 variant where `xx` can be for example `c3`, `c6`, `s2`, `s3`. You need to pick the right variant when creating your ESPHome config.
- If you have a single-core ESP32 device you need to compile ESPHome with single-core support or it will fail to boot.  If your device is single-core or you are not sure, add the following to your config:

```yaml
esp32:
  ...
  framework:
    type: esp-idf
    sdkconfig_options:
      CONFIG_FREERTOS_UNICORE: y
```

## Getting the Binary

Then, generate and download the firmware image:

### Using the Home Assistant add-on/dashboard

From the card of your device: open **the three dots menu** and select **Install** option.

<Image src={dashboardInstallImg} layout="constrained" alt="" />

A new dialog will open. Click on **Manual download** option.

<Image src={dashboardInstallManualImg} layout="constrained" alt="" />

Finally, choose **factory format** (formerly "modern format") in the last dialog.

<Image src={dashboardInstallManualModernImg} layout="constrained" alt="" />

The build process of the firmware will start and the image will be automatically downloaded after its completion.

### Using the command line

From your configuration files folder, run

```shell
esphome compile <MY_DEVICE>.yaml
```

replacing `<MY_DEVICE>.yaml` with your configuration file and navigate to the
`<MY_DEVICE>/.pioenvs/<MY_DEVICE>/` folder.

There you will find a `firmware.bin` file. This is the binary that you will upload.

## Uploading the Binary

To upload the binary, navigate to the Tasmota web interface and enter the
"Firmware Upgrade" section.

<Image src={tasmotaMainImg} layout="constrained" alt="" />

In the "Upgrade by file upload" section, choose the binary you previously downloaded

<Image src={tasmotaOtaImg} layout="constrained" alt="" />

If everything succeeds, you will see an "Upload Successful" message and ESPHome
will connect to the WiFi network configured in your .yaml file. 🎉

> [!NOTE]
> When using the [esp8266_pwm output](/components/output/esp8266_pwm/) platform and
> switching from Tasmota, you need to power-cycle the device once. After that
> the dimming functionality will work as usual and no more power cycles are required.

## About image size and ESP8266

ESP8266 has very limited storage space. Trying to upload a large image will cause the
upgrade process to fail.

Tasmota 8.2 introduced upgrading using gzipped binaries which are smaller in size and
make the upgrade process easier.

- If you are using Tasmota 8.2 or later (recommended) you probably will want to compress the firmware generated from
  ESPHome with `gzip` before uploading it.

- If you are using any version older than 8.2: first upload `tasmota-minimal.bin` from Tasmota repository. Then
  upload the firmware generated from ESPHome.

- Alternatively, first upgrade Tasmota to the latest version. Then use the first (gzip, recommended) method.

    If you are using Tasmota 7.2+ it may be necessary to run the command `SetOption78 1` in the
    Tasmota console and restart your device to be able to upgrade to esphome.

## Automated migration from console

You may also use Tasmota console to invoke the upgrade with just two commands:

```text
OtaUrl http://<MY-ESPHOME:6052>/download.bin?configuration=<MY_DEVICE>.yaml&file=firmware.bin&compressed=1
Upgrade 1
```

replacing `http://<MY-ESPHOME:6052>/` with the host and port of your ESPHome installation and `<MY_DEVICE>.yaml`
with your device configuration file name.

If you need to use the uncompressed image for any reason, just remove `&compressed=1` from the above url.

## Partition table migration via OTA (for ESP32 devices with Tasmota v12 or higher)

After uploading ESPHome to your ESP32 device you need to update the partition table. Regular OTA updates are impossible until this step is completed.

To update the partition table, open the logs to see more detailed information about potential errors. Then run the following command in a command line:

```shell
esphome upload --partition-table <MY_DEVICE>.yaml
```

If the update was successful, the ESP will reboot. You can now remove the line `allow_partition_access: true` from your config, add more components and install ESPHome updates via OTA.
