The `daikin_madoka` component creates a climate device that controls a Daikin Madoka (BRC1H)
wired controller over Bluetooth, the way the Daikin smartphone app does.

<Figure
  src={MadokaControllerImg}
  alt="Daikin Madoka controller"
  layout="constrained"
/>

This component supports the following functionality:

- Set the operating mode: off, heat, cool, dry, fan only, heat/cool (auto)
- Set the cooling and heating target temperatures (two-setpoint mode)
- Show the current room temperature
- Set the fan speed: auto, low, medium, high

## Base Configuration

```yaml
# Example configuration entry
esp32_ble_tracker:

esp32_ble:
  io_capability: display_yes_no

ble_client:
  - mac_address: XX:XX:XX:XX:XX:XX
    id: madoka_climate

climate:
  - platform: daikin_madoka
    name: "Madoka Climate"
    ble_client_id: madoka_climate
```

## Configuration Variables

- **ble_client_id** (**Required**, [ID](/guides/configuration-types/#id)): The ID of the
  [BLE Client](/components/ble_client/) used for the communication.
- **update_interval** (*Optional*, [Time](/guides/configuration-types/#time)): The interval to check the
  device for state updates. Defaults to `10s`.
- All other options from [Climate](/components/climate/#config-climate).

## Pairing

The controller expects to pair with a smartphone and compares a pairing code with it, so `esp32_ble`
needs `io_capability: display_yes_no` or `keyboard_display`; the configuration is rejected otherwise.

On the first connection the Madoka shows a pairing code and asks you to confirm it on the controller.
The ESP32 logs the same code and accepts it automatically, so confirming on the Madoka is the only
manual step. The ESP32 keeps the bond, so the question does not come back on later connections.
