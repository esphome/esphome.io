The nRF52 platform supports firmware updates via Over-the-Air (OTA) mechanisms. The **only supported bootloader** for OTA updates is **MCUboot**.

> [!NOTE]
> This OTA platform also works on `platform: zephyr` builds — variant: `nrf52`, `nrf54l15`,
> `nrf54lm20a`, `efr32mg24`, `rp2040`, and `rp2350` — not just the legacy `platform: nrf52` component
> named in this page's title. See the [Zephyr platform's variant table](/components/zephyr/#variants).

To flash firmware onto the device, you can use any of the tools or libraries listed in the [Zephyr MCUmgr documentation](https://docs.zephyrproject.org/latest/services/device_mgmt/mcumgr.html#tools-libraries).
Firmware updates are also available via the ESPHome command-line interface.
For flashing over **BLE**, the [MCUmgr Web Tool](https://boogie.github.io/mcumgr-web/) provides a convenient browser-based interface.

In addition to OTA updates, ESPHome also supports a "safe mode" to help with recovery if/when updates don't work as
expected. This is automatically enabled by this component, but it may be disabled if desired. See
[Safe Mode](/components/safe_mode/) for details.

```yaml
# Example configuration entry
ota:
  - platform: zephyr_mcumgr
```

## Configuration variables

- **transport** (*Optional*, mapping): Specifies the transport method used by Zephyr MCUmgr for OTA updates. By default, Bluetooth Low Energy (`ble: true`) is enabled.
- **swap_method** (*Optional*, string): `platform: zephyr` only. The MCUboot image-swap algorithm to
  use for applying an update. Same option, same per-variant defaults and support, as
  [`ota: platform: esphome`'s `swap_method`](/components/ota/esphome/#configuration-variables) — see
  that page for the full list. Not applicable to the legacy `platform: nrf52` component.

## `transport`

Zephyr MCUmgr can operate over multiple transport protocols, which are selected via configuration options.

```yaml
# Example configuration entry
ota:
  - platform: zephyr_mcumgr
    transport:
      ble: true
      hardware_uart: CDC
```

### Configuration variables

- **ble** (*Optional*, boolean): Enable Bluetooth Low Energy transport for MCUmgr OTA. Default `false`.
- **hardware_uart** (*Optional*, enum): Select a hardware UART interface to use for MCUmgr OTA communication. This is used when updating devices over a serial interface rather than BLE. Options: `CDC`, `CDC1`, `UART0`, `UART1`. `CDC`/`CDC1` (USB CDC-ACM) need a board with a USB peripheral — the legacy `platform: nrf52` component and `platform: zephyr`'s Nordic-family variants (`nrf52`, `nrf54l15`, `nrf54lm20a`) have one; `efr32mg24` doesn't, so only `UART0` (its one physical UART, `usart0`) or `ble: true` are valid there.

## Usage

To connect and update the device over BLE:

```bash
esphome upload nrf52_device.yaml --device BLE
```

Or connect to a specific BLE address:

```bash
esphome upload nrf52_device.yaml --device 00:11:22:33:44:55
```

To connect and update the device over serial:

```bash
esphome upload nrf52_device.yaml
```

Or connect to a specific serial:

```bash
esphome upload nrf52_device.yaml --device /dev/ttyACM0
```
