title: "ThermoPro TempSpike Plus TP970"
description: "Receive TempSpike Plus TP970 probe temperatures through Bluetooth GATT notifications."
---

The `thermopro_tp970` component connects an ESP32 to a ThermoPro TempSpike Plus TP970 booster and receives
probe temperatures through Bluetooth GATT notifications. It supports the single-probe TP970 Plus, which
advertises as `TP970R`. Other TempSpike models have not been tested.

This component requires an [ESP32 BLE Tracker](/components/esp32_ble_tracker/) and a
[BLE Client](/components/ble_client/) configured with the booster's Bluetooth MAC address.
It uses one BLE connection slot and maintains the connection while the probe is in use.

```yaml
thermopro_tp970:
  id: tempspike
  ble_client_id: tempspike_client

sensor:
  - platform: thermopro_tp970
    thermopro_tp970_id: tempspike
    internal_temperature:
      name: "Probe Internal Temperature"
    ambient_temperature:
      name: "Probe Ambient Temperature"
```

## Setup

Find the booster's MAC address using the BLE tracker logs or a Bluetooth scanner. Configure a `ble_client`
with that address and use its ID as `ble_client_id`. Leave the BLE tracker's default active scanning enabled.
Keep the booster within Bluetooth range of the ESP32 and undock the probe to receive readings.

Close the TempSpike app and other Bluetooth clients before connecting ESPHome. Another client can occupy the
booster's connection. Shelly advertisement scanners cannot provide this GATT connection; the ESP32 connects
directly to the booster.

## Configuration Variables

- **id** (*Optional*, [ID](/guides/configuration-types/#id)): The ID used by the sensor platforms.
- **ble_client_id** (**Required**, [ID](/guides/configuration-types/#id)): The BLE client for the booster.
- **timeout** (*Optional*, Time): How long to wait without a temperature notification before clearing the
  readings. Defaults to `15s`. The timeout is checked once per second.

### Sensors

Add a `sensor` platform entry with `platform: thermopro_tp970`:

- **thermopro_tp970_id** (*Optional*, [ID](/guides/configuration-types/#id)): The component to use. Required
  when there is more than one instance.
- **internal_temperature** (*Optional*): Probe internal temperature in degrees Celsius.
- **ambient_temperature** (*Optional*): Probe ambient temperature in degrees Celsius.
- **battery_level** (*Optional*): Estimated battery percentage, using an empirical TP96/TP97 battery curve.
- **notification_count** (*Optional*): Number of recognized probe temperature messages since the ESP32
  started. This diagnostic counts messages even when the temperature does not change.

Each sensor accepts all options from [Sensor](/components/sensor/).

### Binary Sensor

Add a `binary_sensor` platform entry with `platform: thermopro_tp970`:

- **thermopro_tp970_id** (*Optional*, [ID](/guides/configuration-types/#id)): The component to use. Required
  when there is more than one instance.
- **temperature_stream** (*Optional*): On while recognized probe temperature messages are arriving and have
  not timed out. This reports message freshness, rather than just the Bluetooth connection state.
  Accepts all options from [Binary Sensor](/components/binary_sensor/).

```yaml
binary_sensor:
  - platform: thermopro_tp970
    thermopro_tp970_id: tempspike
    temperature_stream:
      name: "Probe Temperature Stream"
```

## Updates And Missing Readings

Temperature notifications normally arrive about every three seconds, with occasional additional messages.
ESPHome publishes each recognized message without a polling interval. Home Assistant can suppress unchanged
temperature states; use `notification_count` and `temperature_stream` to check reception.

The device's `0xFFFF` invalid value is converted to `NaN` separately for each temperature and battery field.
Disconnection or a notification timeout clears all three readings. Home Assistant can display these missing
numeric values as unknown. A connection resumes automatically when the booster is advertising and the BLE
client has `auto_connect` enabled, which is its default.

Docking can stop the stream, but so can loss of Bluetooth range or power. The component therefore does not
expose a docked sensor.
