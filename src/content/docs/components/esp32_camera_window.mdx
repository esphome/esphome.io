The `esp32_camera_window` component restricts the readout of an [ESP32 Camera](/components/esp32_camera/) sensor to a
rectangular part of the picture, a *window*. Only the part of the sensor covered by the window is read out at all, so
pixels outside it are never read out.

The window is measured from the top left corner of the published frame, with `(0, 0)` there, so the same window
always asks for the same part of the picture whatever frame size is in use. A window that reaches past the frame is
clamped to it.

How a window maps onto the published frame depends on the sensor:

| Sensor             | Published frame           | Notes                                    |
| ------------------ | ------------------------- | ---------------------------------------- |
| OV2640             | The size of the window    | JPEG output only, rounded to 16x8 blocks |
| OV3660, OV5640     | The configured frame size | Scaled to the frame, so it also zooms in |
| SC101IOT, SC030IOT | The configured frame size | `width` and `height` must be the frame   |

On the SC101IOT and SC030IOT the offsets are counted in the pixels of the whole sensor readout from its top left
corner, 1280x720 for the SC101IOT and 640x480 for the SC030IOT, and a window of another size is rejected.

A window set at runtime replaces the previous one, and never nests inside it. Changing the frame size through the
camera clears the window back to the whole sensor, so re-apply it afterwards; one or two captures after a change
may still show the previous window.

Every other sensor the camera driver knows — the OV7725, OV7670, OV3640, NT99141, GC2145, GC032A, GC0308, BF3005,
BF20A6, SC031GS, HM1055, HM0360 and MEGA_CCM — is read out through registers of its own, so a window is reported as
unsupported and every call to set one fails on it. A camera with such a sensor is otherwise unaffected: a `window` in
the configuration is skipped with a warning at startup.

Requires an [ESP32 Camera](/components/esp32_camera/) to be configured.

```yaml
# Example configuration entry
esp32_camera_window:
  camera_id: my_camera
  window:
    offset_x: 100
    offset_y: 200
    width: 320
    height: 240
```

## Configuration variables

- **camera_id** (**Required**, [ID](/guides/configuration-types#id)): The ID of the
  [ESP32 Camera](/components/esp32_camera/) to read a window out of.
- **id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID used for code generation.

Window Options:

- **window** (*Optional*): The window to apply at startup. If not set, no window is applied and the whole sensor is
  read out. On the SC101IOT and SC030IOT the window has to be the size of the frame. On the OV2640 the published
  frame takes the size of the window instead of keeping the configured size.

  - **offset_x** (**Required**, int): The horizontal offset of the window in pixels, counted from the left edge of
    the published frame, or of the whole sensor readout on the SC101IOT and SC030IOT. Must be `0` or greater.
  - **offset_y** (**Required**, int): The vertical offset of the window in pixels, counted from the top edge of the
    published frame, or of the whole sensor readout on the SC101IOT and SC030IOT. Must be `0` or greater.
  - **width** (**Required**, int): The width of the window in pixels. Must be `1` or greater.
  - **height** (**Required**, int): The height of the window in pixels. Must be `1` or greater.

## Automations

### `esp32_camera_window.set` Action

This action reads out a window of the camera. It has the same effect as the `window` option above, but can be used at
runtime.

```yaml
on_...:
  then:
    - esp32_camera_window.set:
        id: my_window
        offset_x: 300
        offset_y: 100
        width: 320
        height: 240
```

Configuration variables:

- **id** (**Required**, [ID](/guides/configuration-types#id)): The ID of the `esp32_camera_window` component.
- **offset_x** (**Required**, int): The horizontal offset of the window in pixels, counted from the left edge of the
  published frame, or of the whole sensor readout on the SC101IOT and SC030IOT.
- **offset_y** (**Required**, int): The vertical offset of the window in pixels, counted from the top edge of the
  published frame, or of the whole sensor readout on the SC101IOT and SC030IOT.
- **width** (**Required**, int): The width of the window in pixels.
- **height** (**Required**, int): The height of the window in pixels.

On the OV3660 and OV5640 the frame size the camera publishes is left as it is; on the OV2640 the published frame
takes the size of the window instead.

On the SC101IOT and SC030IOT, `width` and `height` have to be the size of the frame, and a window of another size is
rejected.

### `esp32_camera_window.reset` Action

This action reads out the whole sensor again. The configured frame size stays the same; on the OV2640 the published
frames return from the window size to the full size.

```yaml
on_...:
  then:
    - esp32_camera_window.reset: my_window
```

Configuration variables:

- **id** (**Required**, [ID](/guides/configuration-types#id)): The ID of the `esp32_camera_window` component.

## Choosing a Window

> [!TIP]
> Use the community [ESP32 Camera ROI Tool](https://nliaudat.github.io/esphome_ai_component/roi.html) to pick
> `offset_x`, `offset_y`, `width` and `height` visually instead of guessing pixel values.

The tool lets you load a sample frame, select the sensor full resolution (`OV2640` up to `1600x1200` UXGA,
`OV3660` up to `2048x1536` QXGA, `OV5640` up to `2592x1944` QSXGA), draw the region of interest, optionally set
rotation and a target resolution, and then copies the computed offsets and size into your `window` configuration
or `esp32_camera_window.set` action. It also snaps values to the alignment the hardware requires. The tool
covers the scaling sensors; on the `SC101IOT` (`1280x720`) and `SC030IOT` (`640x480`) enter the offsets manually
and keep `width` and `height` equal to the frame size. On the `OV2640` the published frame takes the window size,
so pick the window at the size you want to receive.

## Hardware Windowing Details

The exact calculation of windowing is complex and depends mainly on your hardware.

On the OV2640, windowing defines a region of interest (ROI) anywhere inside the `1632x1220` boundary. From the
[OV2640 datasheet](https://www.uctronics.com/download/cam_module/OV2640DS.pdf):

> The OV2640 allows the user to define window size or region of interest (ROI), as required by the application.
> Window size setting (in pixels) ranges from 2 x 4 to 1632 x 1220 (UXGA) or 2 x 2 to 818 x 610 (SVGA), and
> 408 x 304 (CIF), and can be anywhere inside the 1632 x 1220 boundary.

To define the window, the driver programs these register groups. The OV2640 uses register banks, so the correct
bank (`BANK_SENSOR` or `BANK_DSP`) must be selected before reading or writing:

| Register Name | Register Address       | Description                                        |
| ------------- | ---------------------- | -------------------------------------------------- |
| `HSTART`      | `0x17` (`BANK_SENSOR`) | High 8 bits of the horizontal start position.      |
| `HREF`        | `0x32` (`BANK_DSP`)    | Low 2 bits of `HSTART` (`[7:6]`) and `HSTOP` (`[5:4]`). |
| `VSTART`      | `0x19` (`BANK_SENSOR`) | High 8 bits of the vertical start position.        |
| `VREF`        | `0x03` (`BANK_DSP`)    | Low 2 bits of `VSTART` (`[7:6]`) and `VSTOP` (`[5:4]`). |
| `HSTOP`       | `0x18` (`BANK_SENSOR`) | High 8 bits of the horizontal end position.        |
| `VSTOP`       | `0x1A` (`BANK_SENSOR`) | High 8 bits of the vertical end position.          |

```text
Figure 4 concept, redrawn (OV2640 datasheet): Windowing

                          Column Start          Column End
                                |                    |
                   HREF --------+--------------------+--------
                                v                    v
                     +------------------------------------------+
                     |//////////////////////////////////////////|
                     |//////////////////////////////////////////|
           Row Start |--------->+--------------------+//////////|
        R   (HREF)   |//////////|                    |//////////|
        o            |//////////|   Display Window   |//////////|  Sensor
        w            |//////////|                    |//////////|  Array
           Row End   |--------->+--------------------+//////////|  Boundary
        v            |//////////////////////////////////////////|
                     +------------------------------------------+
```

`///` marks sensor areas outside the window; only the Display Window is read out.
Column Start/End map to `HSTART`/`HSTOP` and Row Start/End to `VSTART`/`VSTOP` in the formulas below.

The start and stop values are 10-bit numbers spread across two registers:

- Horizontal start: `(HSTART[7:0] << 2) | HREF[7:6]`
- Horizontal stop: `(HSTOP[7:0] << 2) | HREF[5:4]`
- Vertical start: `(VSTART[7:0] << 2) | VREF[7:6]`
- Vertical stop: `(VSTOP[7:0] << 2) | VREF[5:4]`

The window size is then:

- Window width = `HSTOP - HSTART`
- Window height = `VSTOP - VSTART`

You do not need to program these registers by hand; `esp32_camera_window` and the ROI tool above handle this
for you.
