The `esp32_camera_window` component restricts the readout of an [ESP32 Camera](/components/esp32_camera/) sensor to a
rectangular part of the picture, a *window*. Only the part of the sensor covered by the window is read out at all, so
pixels outside it are never read out.

The camera keeps publishing frames of the size it is configured with. The window is measured from the top left corner of
the published frame, with `(0, 0)` there, so the same window always asks for the same part of the picture whatever
frame size is in use. A window that reaches past the frame is clamped to it.

Windows are supported by the OV2640, OV3660 and OV5640, which scale the part of the picture a window covers back up to
the frame, so a window on them also zooms in and a window smaller than the frame fills the whole frame on its own. The
OV2640 can only crop in whole four-pixel steps, so a window on it is rounded down to one.

The SC101IOT and SC030IOT are supported as well, but they read a window out as it is and cannot scale it, so a window
on them has to be the size of the frame and only moves which part of the sensor the frame shows. The offsets of such a
window are counted in the pixels of the whole sensor readout from its top left corner, 1280x720 for the SC101IOT and
640x480 for the SC030IOT, and a window of another size is rejected.

Every other sensor the camera driver knows, among them the OV7725, the OV7670, the GC and BF sensors, the SC031GS,
the NT99141, the HM sensors and the MEGA_CCM, is read out through registers of its own, so a window is reported as
unsupported and every call to set one fails on it. A camera with such a sensor is otherwise unaffected: a `window` in
the configuration is skipped with a warning at startup.

Requires an [ESP32 Camera](/components/esp32_camera/) to be configured.

```yaml
# Example configuration entry
esp32_camera_window:
  camera_id: my_camera
  window:
    offset_x: 100
    offset_y: 200
    width: 320
    height: 240
```

## Configuration variables

- **camera_id** (**Required**, [ID](/guides/configuration-types#id)): The ID of the
  [ESP32 Camera](/components/esp32_camera/) to read a window out of.
- **id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID used for code generation.

Window Options:

- **window** (*Optional*): The window to apply at startup. If not set, no window is applied and the whole sensor is
  read out. On the SC101IOT and SC030IOT the window has to be the size of the frame.

  - **offset_x** (**Required**, int): The horizontal offset of the window in pixels, counted from the left edge of
    the published frame, or of the whole sensor readout on the SC101IOT and SC030IOT. Must be `0` or greater.
  - **offset_y** (**Required**, int): The vertical offset of the window in pixels, counted from the top edge of the
    published frame, or of the whole sensor readout on the SC101IOT and SC030IOT. Must be `0` or greater.
  - **width** (**Required**, int): The width of the window in pixels. Must be `1` or greater.
  - **height** (**Required**, int): The height of the window in pixels. Must be `1` or greater.

## Automations

### `esp32_camera_window.set` Action

This action reads out a window of the camera. It has the same effect as the `window` option above, but can be used at
runtime.

```yaml
on_...:
  then:
    - esp32_camera_window.set:
        id: my_window
        offset_x: 300
        offset_y: 100
        width: 320
        height: 240
```

Configuration variables:

- **id** (**Required**, [ID](/guides/configuration-types#id)): The ID of the `esp32_camera_window` component.
- **offset_x** (**Required**, int): The horizontal offset of the window in pixels, counted from the left edge of the
  published frame, or of the whole sensor readout on the SC101IOT and SC030IOT.
- **offset_y** (**Required**, int): The vertical offset of the window in pixels, counted from the top edge of the
  published frame, or of the whole sensor readout on the SC101IOT and SC030IOT.
- **width** (**Required**, int): The width of the window in pixels.
- **height** (**Required**, int): The height of the window in pixels.

On the SC101IOT and SC030IOT, `width` and `height` have to be the size of the frame, and a window of another size is
rejected.

### `esp32_camera_window.reset` Action

This action reads out the whole sensor again, without changing the frame size the camera publishes.

```yaml
on_...:
  then:
    - esp32_camera_window.reset: my_window
```

Configuration variables:

- **id** (**Required**, [ID](/guides/configuration-types#id)): The ID of the `esp32_camera_window` component.
