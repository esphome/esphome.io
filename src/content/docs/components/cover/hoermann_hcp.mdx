The `hoermann_hcp` component allows you to control Hörmann garage door operators through the HCP bus built
into the operator. It emulates the Hörmann UAP1 module, so the operator's bus controller communicates
with ESPHome just like it would with Hörmann's own accessory.

The following Serie 4 operators communicate over the HCP bus (Modbus RTU) and should be supported:

* SupraMatic E/P Serie 4
* ProMatic Serie 4

> [!NOTE]
> Only Serie 4 operators are supported. Older operators use a different connector pinout and a
> completely different protocol.
>
> This component implements the same protocol as the [HCPBridge](https://github.com/hkiam/HCPBridge)
> project.

Communication with the operator happens over [Modbus](/components/modbus/) with the `role` set to
`server`, which in turn requires a [UART bus](/components/uart/). The UART **must** be configured with
a baud rate of `57600`, even parity and one stop bit.

```yaml
# Example configuration entry
uart:
  id: uart_bus
  tx_pin: GPIOXX
  rx_pin: GPIOXX
  baud_rate: 57600
  parity: EVEN
  stop_bits: 1

modbus:
  uart_id: uart_bus
  role: server

hoermann_hcp:

cover:
  - platform: hoermann_hcp
    name: Garage Door
    device_class: garage
```

## Hardware

The HCP bus is a two-wire RS485 connection that also carries the operator's ~25 V supply, so a single
cable provides both communication and power — no separate power supply is required. To connect an
ESP32 (or another ESPHome-supported chip) you need three things:

- an **RS485 transceiver** wired to the [UART bus](/components/uart/);
- a **step-down (buck) converter** that derives 5 V for the ESP32 and the transceiver from the bus
  voltage; and
- a **120 Ω termination resistor** across the RS485 data lines, as required by the RS485/Modbus
  standard.

The operator exposes the bus on a 6-pin socket with the following pinout:

| Pin | Signal          | Example wire colour |
| --- | --------------- | ------------------- |
| 1   | GND             | Blue                |
| 2   | GND             | Yellow              |
| 3   | B− (RS485 data) | Green               |
| 4   | A+ (RS485 data) | Red                 |
| 5   | +25 V           | Black               |
| 6   | +25 V           | White               |

> [!NOTE]
> The wire colours depend on the cable you use — the pin positions are what matter. The GND (pins 1
> and 2) and +25 V (pins 5 and 6) contacts are each duplicated on the operator side, so you only need
> to connect **one** pin from each pair.

Wire the adapter as shown below: a +25 V pin feeds the buck converter's input, its 5 V output powers
both the ESP32 and the RS485 transceiver, the A+/B− data lines connect to the transceiver (with the
120 Ω resistor bridging them), and the transceiver's serial pins connect to the ESP32 UART pins you
set in the `uart:` block.

> [!NOTE]
> The example above uses a transceiver module with automatic direction control, so no separate DE/RE
> flow-control pin is needed. If your module labels its serial pins differently, connect its receiver
> output (RO/RXD) to the ESP32 `rx_pin` and its driver input (DI/TXD) to the ESP32 `tx_pin`; swap the
> two if data doesn't flow.

> [!IMPORTANT]
> The operator only powers the adapter after a successful bus scan. Trigger a bus scan from the
> operator's menu with the adapter connected; the operator keeps supplying power only if the adapter
> answers during the scan.

## Component/Hub

The `hoermann_hcp` hub handles the communication with the operator's bus controller and exposes its state
to the `cover` platform below.

### Configuration variables

- **id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID used for code
  generation.
- **modbus_id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID of the
  [Modbus](/components/modbus/) hub.
- **address** (*Optional*, int): The Modbus server address the component answers on. Defaults to `2`,
  which is the address the operator's bus controller expects the UAP1 module on. You should not need
  to change this.
- **update_interval** (*Optional*, [Time](/guides/configuration-types#time)): The interval at which
  the connection to the bus controller is checked. Defaults to `500ms`.

## Cover

The `hoermann_hcp` cover platform exposes the garage door as a [cover](/components/cover/). It supports
opening, closing, stopping and moving to a position, and reports the position and operation as
provided by the operator.

```yaml
cover:
  - platform: hoermann_hcp
    name: Garage Door
    device_class: garage
```

### Configuration variables

- **hoermann_hcp_id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID of the
  `hoermann_hcp` hub. Only required if you have more than one hub.
- All other options from [Cover](/components/cover#config-cover).
