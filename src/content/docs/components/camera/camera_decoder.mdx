The `camera_decoder` component decodes JPEG frames from a camera into a pixel
buffer. It is the decoder counterpart of
[camera_encoder](/components/camera/camera_encoder/), for components that need
pixels rather than the encoded JPEG.

```yaml
camera_decoder:
  id: camera_pixels
  type: esp32_camera
  output_type: RGB888
  rotation: 0
```

The decoder owns its output buffer and reuses it across decodes when the size
allows, so a consumer can decode repeatedly without allocating every frame.

## Configuration variables

- **id** (*Optional*, [ID](/guides/configuration-types/#id)): The decoder ID.
- **type** (*Optional*): The decoder implementation. `esp32_camera`.
- **output_type** (*Optional*): `RGB888` (default), `RGB565` or `YUV422`.
- **rotation** (*Optional*, int): `0` (default), `90`, `180` or `270` degrees,
  applied while decoding. The image dimensions must be multiples of 8 for
  rotation.

## C++ API

The decoder implements `camera::Decoder`:

```cpp
auto error = decoder->decode(data, length, &spec);
if (error == camera::DECODER_ERROR_SUCCESS) {
  camera::Buffer *pixels = decoder->get_output_buffer();
  // spec.width, spec.height and spec.format describe the buffer.
}
```

`spec` is a `camera::CameraImageSpec`. Supported output formats are
`camera::PIXEL_FORMAT_RGB888`, `PIXEL_FORMAT_RGB565` and
`PIXEL_FORMAT_YUV422`.

## Notes

- Decoding uses `espressif/esp_new_jpeg` 1.0.2.
- Grayscale output is not supported by the decoder; decode to `RGB888` and
  convert if needed.
- This component does not crop, scale, split zones or normalize output. Use it
  together with a consumer that does.
