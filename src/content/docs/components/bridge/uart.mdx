The UART Bridge (the `uart` platform of the [Bridge](/components/bridge/) component) copies bytes unchanged, in both
directions, between two [UART buses](/components/uart/). Each bus keeps its own baud rate, data bits, parity and stop
bits, so two serial devices with different settings can talk to each other through this device.

The example assumes two UART buses with the IDs `device_a` and `device_b` are configured.

```yaml
# Example configuration entry
bridge:
  - platform: uart
    uart_id: device_a
    peer_id: device_b
```

## Configuration Variables

- **uart_id** (**Required**, [ID](/guides/configuration-types/#id)): The ID of one UART bus.
- **peer_id** (**Required**, [ID](/guides/configuration-types/#id)): The ID of the other UART bus. The same bus on
  both sides is rejected.
- **id** (*Optional*, [ID](/guides/configuration-types/#id)): Manually specify the ID for this component.

> [!NOTE]
> A bridge requires exclusive use of both buses. A configuration where another component (through `uart_id`) or
> another bridge also uses either bus is rejected, and so is `dummy_receiver` in the
> [debug](/components/uart/#debugging) option of either bus.

## How It Works

- Bytes from a bus are collected until it has been quiet for a frame gap, or until 256 bytes are in. On a serial line
  the gap is 3.5 characters, at least 1.75 ms. A UART whose bytes arrive in packets (for example over TCP or USB), or
  one without a baud rate, uses 50 ms.
  A pause inside a frame longer than 1.5 characters (longer than three quarters of the 50 ms for a UART with packets)
  can end the frame early.
- A block that starts a frame is sent once the destination line has been quiet for a frame gap.
- A frame longer than 256 bytes goes out in blocks and can pause between them.
- Bytes for a side that is not connected, or that takes nothing for one second, are dropped with a warning.
- On ESP32, a pause inside a frame of about `rx_timeout` characters or longer can split the frame in two.
- On a serial line whose UART cannot report how much it can take, for example on RP2040 and LibreTiny (not on
  ESP8266), a frame of up to 255 bytes goes out in one piece. Anything longer goes out at the line rate in small
  pieces, so the other direction is still read meanwhile. It can pause while the device is busy elsewhere for longer
  than the transmit FIFO lasts (32 characters on an RP2040 hardware UART: about 2.8 ms at 115200 baud).
