---
description: "Debug tooling for TFLite Micro models (architecture, tensors, parameter sweeps)"
title: "TFLite Model Debug"
---

The `tflite_model_debug` component is a **library-only component**: it has no user-facing configuration options and is
loaded automatically as a dependency of the `tflite_micro_runtime`
component and of the third-party components that consume it.

The definitions are compiled in whenever this component is present: `USE_TFLITE_MODEL_DEBUG` is emitted by its
own code generation and declares the debug members on `ModelHandler`. The `debug:` option of the consuming
`tflite_micro_runtime` instance is a runtime flag that turns the diagnostics on for that instance, so nothing is
compiled out when it is `false`. The diagnostics are model architecture inspection, tensor input/output
statistics and quantization analysis, parameter sweeps for tuning preprocessing configuration, and watchdog
feeding during long debug operations. Model data integrity is not one of them: the CRC32 is verified by
`tflite_model_loader` on every load.

## Example configuration entry

The component has no options of its own: the diagnostics are enabled with `debug: true` on the
`tflite_micro_runtime` instance that loads it:

```yaml
tflite_micro_runtime:
  - id: digit_reader
    model_type: image
    model: "models/digit_recognizer.tflite"
    tensor_arena_size: 200KB
    # Enables the tflite_model_debug diagnostics for this instance
    debug: true
```

## Configuration Variables

This component has no configuration variables of its own: it is loaded automatically by `tflite_micro_runtime`,
which owns the user-facing options. The diagnostics are enabled with `debug: true` on the consuming `tflite_micro_runtime` instance.

The empty schema also allows loading it explicitly, which is mainly useful when another component declares it
in its `DEPENDENCIES` (the ESPHome component tests do this):

```yaml
tflite_model_debug:
```
