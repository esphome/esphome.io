GENIbus is the protocol that Grundfos uses for its own pumps. The `genibus` component is the bus: it builds the
requests, sends them through a transport and passes the answers back. It does not create any sensors or other entities
itself. Device components sit on the bus and turn the pump data into entities.

You do not add `genibus:` to your configuration. It is loaded by a transport, and the transport is the entry you
configure.

## Transports

- [**GENIbus over Bluetooth LE**](/components/genibus_ble/): Talk to a pump over Bluetooth Low Energy (ESP32 only).

## Device Components

A device component reads the data of one pump model and creates its entities. No device component is available on
this bus yet. Device components for specific pumps will follow.

Every device component on the bus accepts these options in addition to its own:

- **genibus_id** (*Optional*, [ID](/guides/configuration-types/#id)): The ID of the transport to use. Required if you
  have more than one transport.

- **address** (*Optional*, int): The GENIbus address of the pump. Each device component sets a default for its pump,
  so you only need this if your pump uses another address.

## How the Bus Works

- **One request at a time.** The bus sends one request and waits for its answer before it sends the next one. If
  several devices are on the same bus, they take turns. Each device has at most one request open.

- **No answer.** If no valid answer arrives within the response timeout, the request ends and the bus sets a warning
  on the component. The next valid answer clears the warning. After a timeout, the bus waits for a short quiet period
  before it sends the next request, so a late answer is not taken for the answer to the next request.

- **Pump without power.** Some pumps lose power for a while, for example when a heating controller switches them off.
  The transport then loses its connection. This is normal and does not set a warning. The bus sends no requests while
  the connection is down, so the log is not filled with errors. A device component can show its values as unknown
  during this time. When the connection comes back, the devices start to read again.

The response timeout, the quiet period and the master address are shown in the log at boot. The transport sets these
values; see its page for the defaults.
