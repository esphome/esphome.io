---
description: "PSRAM-aware tensor arena allocation for TFLite Micro models"
title: "TFLite Memory Handler"
---

The `tflite_memory_handler` component is a **library-only component**: it has no user-facing configuration options and is
loaded automatically as a dependency of the `tflite_micro_runtime`
component and of the third-party components that consume it.

The allocator prefers PSRAM when available and falls back to internal SRAM otherwise; build flags
`-DTFLITE_FORCE_SRAM` and `-DTFLITE_FORCE_PSRAM` override the selection. The arena is allocated with
`RAMAllocator` from the chosen heap and released by a `RAMUniquePtr`, so memory is never leaked when a model is
unloaded; TFLite Micro aligns the buffers it places inside the arena itself.

The component also hosts `ArenaProbe`, which probes the arena size actually required by a model by trial
allocation (progressive increase then binary search), so the requested arena size does not need to be guessed.
It starts from `tensor_arena_size` when that option is set, and otherwise from an estimate computed from the
model's tensors while the configuration is generated; either way the size that is allocated is the one the
probe measured.

## Example configuration entry

The component has no options of its own: the arena it allocates is sized with `tensor_arena_size` on the
`tflite_micro_runtime` instance that loads it (PSRAM is preferred when present):

```yaml
psram:
  mode: quad

tflite_micro_runtime:
  - id: digit_reader
    model_type: image
    model: "models/digit_recognizer.tflite"
    # Tensor arena size: allocated in PSRAM when available, internal RAM otherwise
    tensor_arena_size: 200KB
```

## Configuration Variables

This component has no configuration variables of its own: it is loaded automatically by `tflite_micro_runtime`,
which owns the user-facing options. The arena size is requested with `tensor_arena_size` on the consuming `tflite_micro_runtime` instance; the allocator itself only decides between PSRAM and internal RAM.

The empty schema also allows loading it explicitly, which is mainly useful when another component declares it
in its `DEPENDENCIES` (the ESPHome component tests do this):

```yaml
tflite_memory_handler:
```
