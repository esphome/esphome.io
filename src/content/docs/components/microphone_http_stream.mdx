---
title: "Microphone HTTP Stream"
description: "Stream microphone samples from an ESP32 device over the ESPHome web server."
---

The `microphone_http_stream` component serves one configured [microphone source](/components/microphone/) over HTTP.
It requires the [web server](/components/web_server/) and an ESP32 device. Capture starts when a client connects and
stops after the last client disconnects. It forwards samples from the selected microphone source without resampling.

> [!WARNING]
> A microphone stream can expose private audio. Use this component only on a trusted network. Without web server
> authentication or transport protection, anyone who can reach the device can listen to the microphone.

```yaml
# Example configuration entry
microphone_http_stream:
  stream_id: room_mic
  source:
    microphone: mic_id
```

## Configuration Variables

- **stream_id** (**Required**, string): Stable ID used in the stream URL. Use 1–32 lowercase ASCII letters, digits,
  underscores or hyphens; the first character must be a letter.
- **source** (**Required**, [Microphone Source](/components/microphone/#microphone-source-configuration)): The source
  must output mono, 16-bit PCM. Select a microphone that exposes the desired capture stage.
- **max_clients** (*Optional*, integer): Maximum simultaneous listeners, from `1` to `3`. Defaults to `1`. When set
  above `1`, each listener uses a 128 KiB buffer in PSRAM. Without PSRAM, stream requests fail with HTTP `503`.

## HTTP Endpoints

- `GET /audio/microphones` returns metadata without starting capture. The response includes the stream ID, sample rate,
  number of channels, format, URL and client limit.
- `GET /audio/microphones/{stream_id}` streams the selected microphone. If every configured client slot is in use,
  another request receives HTTP `409`.

The response body contains raw **S16LE mono** samples at the source microphone's configured sample rate. Its content
type is `application/octet-stream`; the `X-Audio-Format`, `X-Audio-Sample-Rate` and `X-Audio-Channels` headers specify
the format. `audio/L16` describes big-endian samples and does not apply here. Every sample occupies two bytes.

For a microphone configured at 16 kHz, this command plays the stream with FFmpeg's `ffplay`:

```bash
curl --no-buffer http://DEVICE_IP/audio/microphones/room_mic | ffplay -f s16le -ar 16000 -ac 1 -
```

Replace `16000` with the `sample_rate_hz` returned by `GET /audio/microphones` if the source uses another rate. The
component uses the source's rate at device startup and does not change it during an active connection. It does not
provide acoustic echo cancellation, noise suppression or wake word detection. To stream audio after processing, that
processing stage must expose its own microphone source and be selected in `source`.
