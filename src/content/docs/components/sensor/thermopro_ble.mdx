The `thermopro_ble` sensor platform lets you track the output of ThermoPro Bluetooth
Low Energy devices using the [Esp32 Ble Tracker](/components/esp32_ble_tracker/). This component will track the
temperature, humidity, battery level and signal strength of the ThermoPro device every time the
sensor sends out a BLE broadcast.

## Supported Devices

This component supports multiple ThermoPro BLE sensor models:

- **TP3xx series** (e.g., TP357S): Temperature, humidity, and battery level sensors. Testing has been primarily done with TP357S devices.
- **TP96x series**: Internal and external temperature sensors with battery level monitoring.
- **TP970**: Internal and external temperature sensors with battery level monitoring.
- **TP972**: Internal and external temperature sensors with battery level monitoring.

All models support signal strength (RSSI) monitoring.

```yaml
# Example configuration entry
esp32_ble_tracker:

sensor:
  # TP3xx series example (TP357S with humidity)
  - platform: thermopro_ble
    mac_address: XX:XX:XX:XX:XX:XX
    temperature:
      name: "ThermoPro Temperature"
    humidity:
      name: "ThermoPro Humidity"
    battery_level:
      name: "ThermoPro Battery Level"
    signal_strength:
      name: "ThermoPro Signal Strength"

  # TP96x/TP970/TP972 example (with external temperature probe)
  # - platform: thermopro_ble
  #   mac_address: YY:YY:YY:YY:YY:YY
  #   temperature:
  #     name: "ThermoPro Internal Temperature"
  #   external_temperature:
  #     name: "ThermoPro External Temperature"
  #   battery_level:
  #     name: "ThermoPro Battery Level"
  #   signal_strength:
  #     name: "ThermoPro Signal Strength"
```

## Configuration variables

- **type** (*Optional*, string): `advertisement` (default) or `gatt`. Existing configurations continue to use advertisements.

- **mac_address** (**Required** for advertisement mode, MAC Address): The MAC address of the ThermoPro device.

- **temperature** (*Optional*): The information for the temperature sensor.

  - All options from [Sensor](/components/sensor/#config-sensor).

- **external_temperature** (*Optional*): The information for the external/probe temperature sensor.
  Some models (TP972, TP970, TP96x) support dual temperature readings - one internal and one from an external probe.

  - All options from [Sensor](/components/sensor/#config-sensor).

- **humidity** (*Optional*): The information for the humidity sensor. Only available on TP3xx devices.

  - All options from [Sensor](/components/sensor/#config-sensor).

- **battery_level** (*Optional*): The information for the battery level sensor.

  - All options from [Sensor](/components/sensor/#config-sensor).

- **signal_strength** (*Optional*): The information for the signal strength (RSSI) sensor.

  - All options from [Sensor](/components/sensor/#config-sensor).

## Setting Up Devices

To set up ThermoPro devices you first need to find their MAC Address so that ESPHome can
identify them. So first, create a simple configuration without any `thermopro_ble` entries
like so:

```yaml
esp32_ble_tracker:
  on_ble_advertise:
    - then:
        - lambda: |-
            char addr[MAC_ADDRESS_PRETTY_BUFFER_SIZE];
            ESP_LOGD("ble_adv", "BLE device address: %s name: %s", x.address_str_to(addr), x.get_name().c_str());
```

After uploading the ESP32 will immediately try to scan for BLE devices such as the ThermoPro, so
you will see messages like this (please note the TPxxxx model name):

```log
[13:36:43][D][ble_adv:042]: BLE device address: XX:XX:XX:XX:XX:XX name: TP357S (XXXX)
```

Note that it can sometimes take some time for the first BLE broadcast to be received.

Then just copy the address (`XX:XX:XX:XX:XX:XX`) into a new `sensor.thermopro_ble` platform
entry like in the configuration example at the top.

> [!NOTE]
> The ThermoPro BLE component listens passively to packets the device sends by itself.
> ESPHome therefore has no impact on the battery life of the device.

## TP970 Connected GATT Mode

For the single-probe TempSpike Plus TP970 (`TP970R`), `type: gatt` maintains a BLE
connection to the booster and subscribes to temperature notifications. This uses the
same temperature and battery decoding as the advertisement mode. It does not depend on
receiving temperature-bearing advertising packets after the connection is established.
Messages arrived approximately every three seconds on the tested TP970; the actual rate
is controlled by the device.

Configure a [BLE Client](/components/ble_client/) named `tempspike_client` with the
booster's MAC address, then add:

```yaml
sensor:
  - platform: thermopro_ble
    type: gatt
    id: tempspike
    ble_client_id: tempspike_client
    temperature:
      name: Food
    external_temperature:
      name: Ambient
    battery_level:
      name: Probe Battery
    notification_count:
      name: Temperature Messages

# Optional freshness indicator
binary_sensor:
  - platform: thermopro_ble
    thermopro_ble_id: tempspike
    temperature_stream:
      name: Temperature Stream
```

In GATT mode, `temperature` is the food/internal temperature and
`external_temperature` is ambient temperature. A `mac_address` is not configured on
the sensor: the referenced BLE client supplies the booster address.

Additional GATT options:

- **ble_client_id** (**Required**, ID): The BLE client connected to the booster.
- **timeout** (*Optional*, Time): Clear readings after this long without a recognized
  temperature notification. Defaults to `15s`, checked once per second.
- **notification_count** (*Optional*): Diagnostic sensor counting recognized temperature
  messages, including messages whose temperature values have not changed.
- **id** (*Optional*, ID): Sensor group ID, used by the optional binary sensor.

The optional `binary_sensor` platform accepts **thermopro_ble_id** (the GATT sensor
ID) and **temperature_stream** (a connectivity binary sensor). It is on while recognized
temperature messages are fresh. It does not establish whether the probe is docked.

Invalid `0xFFFF` fields are cleared independently. Disconnect, GATT close and the
notification timeout clear the temperature and battery readings. Missing messages can
mean docking, range loss or power loss; no docking status is inferred.

GATT mode requires an ESP32 and one available BLE client connection. Humidity and signal
strength options belong to advertisement mode. This component runs directly on the ESPHome
node, not through an advertisement-only Shelly receiver or a Bluetooth proxy. A connected
phone app may compete for the booster connection. Other ThermoPro models are supported by
advertisement mode; connected mode is currently limited to TP970/TP970R.
