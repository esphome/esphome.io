## Component

<span id="ld6004-component"></span>

The `ld6004` component allows you to use the Hi-Link HLK-LD6004 60 GHz 3D presence radar module with
ESPHome. It can track up to 10 people and reports per-target position (X/Y/Z), cluster ID, and Doppler
index.

The [UART](/components/uart/) component is required. `baud_rate`, `data_bits`, `parity` and
`stop_bits` **must be** `115200`, `8`, `NONE` and `1`.

```yaml
# Example configuration entry
ld6004:
  id: ld6004_radar
```

### Configuration Variables

- **id** (*Optional*, [ID](/guides/configuration-types/#id)): Manually specify the ID for this component.
- **uart_id** (*Optional*, [ID](/guides/configuration-types/#id)): Manually specify the ID of the
  [UART Component](/components/uart/) to use. Required if you have multiple UARTs configured.

> [!NOTE]
> The LD6004 has no `wakeup_pin`, `wakeup_pulse`, or `auto_wake` hub options and no `wake` button.
> Configure low-power operation with the `work_mode` select. There is no `low_power` switch.

## Power and Hardware Requirements

Connect the radar TX to the microcontroller RX, radar RX to microcontroller TX, and connect their grounds.
The module's OUT / P20 pin is a configurable digital output. Connect it to a microcontroller input to read
its level with a [GPIO Binary Sensor](/components/binary_sensor/gpio/).
See [Reading the OUT Pin](#reading-the-out-pin) for an example.

Use the supply requirements and connector pinout specified for your LD6004 module.

## Specifications

- Operating frequency: 60 GHz.
- Maximum tracked targets: 10.
- Target reports: X/Y/Z coordinates, cluster ID, and Doppler index.
- Configurable areas: four interference areas, four detection areas, and four dwell areas.

## Installation and Coordinate System

The module supports top and side mounting. Set `installation_mode` to match the installation.
Mount the antenna side facing the detection area.

Target and area coordinates are reported in meters. The origin is the module projection onto the
reference plane (floor for ceiling installs, wall for side installs). X is left/right, Y is
forward/away, and Z is height. Detection, interference, and dwell areas are configured relative to this
origin.

> [!NOTE]
> Detection distance varies with target size and environment. Some variation is expected.

## Area Configuration Notes

Detection areas define where presence is considered valid for the presence output modes and the
`detection_area_N` binary sensors. Interference areas mask known noise sources (fans, air
conditioners, curtains) so they do not trigger presence. Areas are stored in the module and persist
across power cycles. Dwell zones are a third area kind, with coordinates available through
`dwell_area_0` to `dwell_area_3`. Use `dwell_lifetime` to set the raw dwell counter and
**Clear Dwell** to clear dwell areas. Dwell areas do not expose separate presence binary sensors.

Use `area_id` to select the area, set `area_config`, then press **Apply Area**. Use **Get Areas** to
read back stored values. A value you set on one of the `area_config` numbers is kept until you apply
it or switch to another `area_id`, so an area read does not overwrite an edit in progress.

> [!NOTE]
> **Apply Area** writes all six coordinates of the selected area, combining the values you set with
> the ones cached from the last area read, which happens on boot and after **Auto Interference**,
> **Clear Interference**, **Reset Detection Area**, and **Clear Dwell**. If a bound is still unknown, the component
> requests the current areas first and applies the update once a fresh report arrives. If that report
> is still incomplete, the update is dropped with a warning.

## Binary Sensor

<span id="ld6004-binary-sensors"></span>

The `ld6004` binary sensor provides presence detection for targets and detection areas.

```yaml
binary_sensor:
  - platform: ld6004
    ld6004_id: ld6004_radar
    target:
      name: Presence
    target_1:
      name: Target-1 Presence
    detection_area_0:
      name: Area-0 Presence
```

### Configuration Variables

- **ld6004_id** (*Optional*, [ID](/guides/configuration-types/#id)): Manually specify the ID of the
  LD6004 component.
- **target** (*Optional*, boolean): True if any target is detected or any detection area reports presence.
  All options from [Binary Sensor](/components/binary_sensor/#config-binary_sensor).
- **target_N** (*Optional*, boolean): True if target slot N (N = 1 to 10) is occupied: `target_1` through
  `target_10`. A person keeps the same slot for as long as they are tracked continuously, and a new
  person takes the lowest free slot. All options from
  [Binary Sensor](/components/binary_sensor/#config-binary_sensor).
- **detection_area_N** (*Optional*, boolean): True if presence is detected in detection area N (0 to 3):
  `detection_area_0`, `detection_area_1`, `detection_area_2`, `detection_area_3`. All options from
  [Binary Sensor](/components/binary_sensor/#config-binary_sensor).

> [!NOTE]
> The `detection_area_N` sensors are cleared when the module reports that it entered unattended
> low-power mode. If a target is still being tracked at that moment the clear is skipped, because a
> tracked target is the more recent statement about the room.

## Sensor

<span id="ld6004-sensors"></span>

The `ld6004` sensor provides target coordinates, point-cloud count, and configured area coordinates.

```yaml
sensor:
  - platform: ld6004
    ld6004_id: ld6004_radar
    target_count:
      name: Target Count
    point_count:
      name: Point Count
    target_1:
      x:
        name: Target-1 X
      y:
        name: Target-1 Y
      z:
        name: Target-1 Z
      doppler_index:
        name: Target-1 Doppler Index
      cluster_id:
        name: Target-1 Cluster
```

### Configuration Variables

- **ld6004_id** (*Optional*, [ID](/guides/configuration-types/#id)): Manually specify the ID of the
  LD6004 component.
- **target_count** (*Optional*, int): Total number of targets currently detected (0 to 10). All options
  from [Sensor](/components/sensor/).
- **point_count** (*Optional*, int): Total number of point-cloud points reported by the radar. All
  options from [Sensor](/components/sensor/).
- **target_N** (*Optional*, configuration): Details about each target (N = 1 to 10). Up to 10 targets can be tracked
  simultaneously: `target_1` through `target_10`. A tracked person keeps the same `target_N`
  slot for as long as they remain tracked, and a new person takes the lowest free slot.

  - **x** (*Optional*, float): X coordinate of the target in meters.
  - **y** (*Optional*, float): Y coordinate of the target in meters.
  - **z** (*Optional*, float): Z coordinate of the target in meters.
  - **doppler_index** (*Optional*, int): Doppler index for the target (speed indicator, not a direct
    speed).
  - **cluster_id** (*Optional*, int): Cluster ID for the target.

  All options above inherit from [Sensor](/components/sensor/).

  Slot identity comes from the module's own spatial clustering, so it is stable rather than perfect:
  two people standing very close together can merge into a single target, a track's cluster ID can
  occasionally change while the person is still in the room, and a slot left by someone who leaves is
  reused by the next new person. Watch `cluster_id` to see when a slot changes hands. It is published
  only when the value changes, not on every frame.

- **interference_area_N** (*Optional*, configuration): Interference (mask) area coordinates (N = 0 to 3). Each area
  provides `x_min`, `x_max`, `y_min`, `y_max`, `z_min`, `z_max` sensors. All options from
  [Sensor](/components/sensor/).

- **detection_area_N** (*Optional*, configuration): Detection area coordinates (N = 0 to 3). Each area provides
  `x_min`, `x_max`, `y_min`, `y_max`, `z_min`, `z_max` sensors. All options from
  [Sensor](/components/sensor/).

- **dwell_area_N** (*Optional*, configuration): Dwell area coordinates (N = 0 to 3), available as
  `dwell_area_0` through `dwell_area_3`.

Each interference, detection, or dwell area accepts these coordinate sensors:

- **x_min** (*Optional*, float): Minimum X coordinate in meters.
- **x_max** (*Optional*, float): Maximum X coordinate in meters.
- **y_min** (*Optional*, float): Minimum Y coordinate in meters.
- **y_max** (*Optional*, float): Maximum Y coordinate in meters.
- **z_min** (*Optional*, float): Minimum Z coordinate in meters.
- **z_max** (*Optional*, float): Maximum Z coordinate in meters.

All coordinate sensors inherit from [Sensor](/components/sensor/).

> [!NOTE]
> The per-target `x`, `y`, `z` and `doppler_index` sensors come with these
> [filters](/components/sensor/#sensor-filters) by default. They hold the last reading for a second, so a
> dropped frame does not read as a gap, and then limit how often updates reach the frontend:
>
> ```yaml
> - timeout:
>     timeout: 1s
>     value: last
> - throttle_with_priority: 1s
> ```
>
> Giving a sensor its own `filters:` replaces the defaults. Use `filters: []` to drop them. For
> example, to get faster updates on a single axis:
>
> ```yaml
>     target_1:
>       x:
>         name: Target-1 X
>         filters:
>           - throttle_with_priority: 300ms
> ```

If a **Target Display** switch is configured, its `restore_mode` decides whether target reporting
starts on boot. The default is `RESTORE_DEFAULT_ON`. Without that switch, the component enables
target reporting automatically when any target sensors or the `work_mode` text sensor are
configured. While target reporting is disabled, target sensors remain `unknown`.

If you configure any area sensors or area configuration numbers, the component requests stored
area data on boot. You can also use **Get Areas** to refresh the values.

> [!NOTE]
> If a `point_cloud` switch is configured, it owns the point cloud stream and its `restore_mode` decides
> the boot state, and turning it off returns `point_count` to `unknown`. Without that switch,
> configuring `point_count` starts the stream on boot on its own.
> The stream sends large frames over the 115200 baud link, so leave it on only while you need the
> count. Configuring the switch or the sensor also reserves a larger 4 KB frame buffer at boot.

## Text Sensor

<span id="ld6004-text-sensors"></span>

The `ld6004` text sensor exposes radar operating mode and firmware version.

```yaml
text_sensor:
  - platform: ld6004
    ld6004_id: ld6004_radar
    work_mode:
      name: Work Mode
    ota_version:
      name: OTA Version
```

### Configuration Variables

- **ld6004_id** (*Optional*, [ID](/guides/configuration-types/#id)): Manually specify the ID of the
  LD6004 component.
- **work_mode** (*Optional*, string): `normal` or `low_power` based on the radar work mode. All options from
  [Text Sensor](/components/text_sensor/#config-text_sensor).
- **ota_version** (*Optional*, string): Firmware version string, if supported by your module firmware. All
  options from [Text Sensor](/components/text_sensor/#config-text_sensor).

> [!NOTE]
> `work_mode` reflects the current operating state and can differ from the `work_mode` select setting.
> If the module firmware does not emit work mode reports, ESPHome falls back to the configured low-power
> setting after a **Get Low Power Mode** request. In this fallback, ESPHome treats any detected presence
> as `normal`.

> [!NOTE]
> This component does not update the radar firmware. Updating the microcontroller through
> [ESPHome OTA](/components/ota/) does not update the radar.

## Number

<span id="ld6004-number"></span>

The `ld6004` number platform lets you configure timing and area coordinates.

```yaml
number:
  - platform: ld6004
    ld6004_id: ld6004_radar
    hold_delay:
      name: Hold Delay (s)
    z_min:
      name: Z Min (m)
    z_max:
      name: Z Max (m)
    low_power_sleep_time:
      name: Low Power Sleep (ms)
    dwell_lifetime:
      name: Dwell Lifetime
    output_interval:
      name: Output Interval (frames)
    area_config:
      x_min:
        name: Area X Min
      x_max:
        name: Area X Max
      y_min:
        name: Area Y Min
      y_max:
        name: Area Y Max
      z_min:
        name: Area Z Min
      z_max:
        name: Area Z Max
```

### Configuration Variables

- **ld6004_id** (*Optional*, [ID](/guides/configuration-types/#id)): Manually specify the ID of the
  LD6004 component.
- **hold_delay** (*Optional*, range `0` to `65535` s, step `1`): Presence hold time, in seconds. All options from
  [Number](/components/number/#config-number).
- **z_min** (*Optional*, range `-10` to `10` m, step `0.1`): Global minimum Z coordinate in meters.
  All options from [Number](/components/number/#config-number).
- **z_max** (*Optional*, range `-10` to `10` m, step `0.1`): Global maximum Z coordinate in meters.
  All options from [Number](/components/number/#config-number).
- **low_power_sleep_time** (*Optional*, range `0` to `60000` ms, step `100`): Low power sleep time in
  milliseconds. When low-power mode is enabled and the area is unattended, the module sleeps for this interval between
  scans. Higher values reduce idle power but increase detection latency. All options from
  [Number](/components/number/#config-number).
- **dwell_lifetime** (*Optional*, range `0` to `16777215`, step `1`): Raw dwell counter.
  The module documentation describes a decrement of 20 per second, without defining the complete
  expiry behavior. All options from [Number](/components/number/#config-number).
- **output_interval** (*Optional*, range `1` to `16777215` frames, step `1`): Report every Nth radar
  frame. The minimum is `1`. All options from [Number](/components/number/#config-number).
- **area_config** (*Optional*, configuration): Coordinate values (`x_min`/`x_max`/`y_min`/`y_max`/`z_min`/`z_max`, each
  range `-10` to `10` m, step `0.1`) for the selected area ID. **Requires** both a `select.area_id` and a
  `button.apply_area` on the same `ld6004` (enforced at compile time). Set the values, then press
  **Apply Area** to send them. A minimum above its matching maximum is rejected with a warning
  instead of being written.

The optional coordinates under `area_config` are:

- **x_min** (*Optional*, number): Minimum X coordinate in meters.
- **x_max** (*Optional*, number): Maximum X coordinate in meters.
- **y_min** (*Optional*, number): Minimum Y coordinate in meters.
- **y_max** (*Optional*, number): Maximum Y coordinate in meters.
- **z_min** (*Optional*, number): Minimum Z coordinate in meters.
- **z_max** (*Optional*, number): Maximum Z coordinate in meters.

Each accepts all options from [Number](/components/number/#config-number).

## Select

<span id="ld6004-select"></span>

The `ld6004` select platform configures sensitivity, trigger speed, installation mode, the
active area ID, work mode, and OUT / P20 behavior.

```yaml
select:
  - platform: ld6004
    ld6004_id: ld6004_radar
    sensitivity:
      name: Sensitivity
    trigger_speed:
      name: Trigger Speed
    installation_mode:
      name: Installation Mode
    area_id:
      name: Area ID
    work_mode:
      name: Work Mode Setting
    p20_mode:
      name: P20 Mode
```

### Configuration Variables

- **ld6004_id** (*Optional*, [ID](/guides/configuration-types/#id)): Manually specify the ID of the
  LD6004 component.
- **sensitivity** (*Optional*, select): `low`, `medium`, or `high`. `low` only detects motion. All options
  from [Select](/components/select/#config-select).
- **trigger_speed** (*Optional*, select): `fast` (~0.5 s), `medium` (~1 s), or `slow` (~5 s), the time from
  detecting a person to triggering. All options from [Select](/components/select/#config-select).
- **installation_mode** (*Optional*, select): `top` or `side`. All options from
  [Select](/components/select/#config-select).
- **area_id** (*Optional*, select): Area to edit with `area_config`. Options are `interference_area_0` through
  `interference_area_3`, `detection_area_0` through `detection_area_3`, and `dwell_area_0` through `dwell_area_3`
  (twelve options mapped internally to IDs 0 to 11). All options from [Select](/components/select/#config-select).

- **work_mode** (*Optional*, select): `normal`, `low_power`, `radar_off_p20_high`,
  `radar_off_p20_low`, or `high_reflectivity`. The radar-off modes disable the radar and hold P20
  high or low. Use this select to enable low-power mode. All options from
  [Select](/components/select/#config-select).
- **p20_mode** (*Optional*, select): Configure the module's OUT / P20 pin. Options are
  `presence_high`, `presence_low`, `constant_low`, `constant_high`, `pulse_low`, and `pulse_high`.
  The presence modes select the active level, the constant modes hold a fixed level, and the pulse
  modes emit a 500 ms pulse on a presence transition. All options from
  [Select](/components/select/#config-select).

The `work_mode` select configures the operating mode. The `work_mode` text sensor reports only
`normal` or `low_power`, so it does not distinguish all five select options.

> [!NOTE]
> If no area ID is selected, **Apply Area** is ignored to prevent writing to the wrong region.

## Switch

<span id="ld6004-switch"></span>

The `ld6004` switch platform enables point-cloud output and target reporting.

```yaml
switch:
  - platform: ld6004
    ld6004_id: ld6004_radar
    point_cloud:
      name: Point Cloud
    target_display:
      name: Target Display
```

### Configuration Variables

- **ld6004_id** (*Optional*, [ID](/guides/configuration-types/#id)): Manually specify the ID of the
  LD6004 component.
- **point_cloud** (*Optional*, switch): Enable or disable point-cloud reporting, which is what `point_count`
  reads. All options from
  [Switch](/components/switch/#config-switch).
- **target_display** (*Optional*, switch): Enable or disable target reporting (`0x0A04`). If disabled, target
  sensors will show `unknown` and target presence binary sensors turn off until re-enabled. All
  options from [Switch](/components/switch/#config-switch).

> [!NOTE]
> Each switch applies its own [`restore_mode`](/components/switch/#config-switch) on boot. `point_cloud`
> keeps the standard `ALWAYS_OFF` default, so enable **Point Cloud** when you want the
> stream. `target_display` defaults to `RESTORE_DEFAULT_ON`, so target reporting starts on unless a
> stored state or your own `restore_mode` says otherwise. `inverted` is not available on these
> switches: they report what the module is doing, not how something is wired to it. The full point
> cloud is not exposed as a text sensor. Use `point_count` to monitor how many points are returned.

The `ld6004` button platform exposes configuration and diagnostic commands.

button:

### Configuration Variables

- **ld6004_id** (*Optional*, [ID](/guides/configuration-types/#id)): Manually specify the ID of the
  LD6004 component.
- **apply_area** (*Optional*, button): Send the configured `area_config` to the selected `area_id`. **Requires**
  a `select.area_id` on the same `ld6004`. All options from [Button](/components/button/#config-button).
- **auto_interference** (*Optional*, button): Generate interference areas from the current environment. Run
  this with no people present and with known interference sources active. To reset the generated
  interference areas, use **Clear Interference**. All options from
  [Button](/components/button/#config-button).
- **get_areas** (*Optional*, button): Request stored interference, detection, and dwell areas from the radar.
  All options from [Button](/components/button/#config-button).
- **clear_interference** (*Optional*, button): Clear interference areas. All options from
  [Button](/components/button/#config-button).
- **reset_detection_area** (*Optional*, button): Reset detection areas to the module defaults. All options
  from [Button](/components/button/#config-button).
- **get_delay** (*Optional*, button): Request hold delay. All options from [Button](/components/button/#config-button).
- **get_sensitivity** (*Optional*, button): Request sensitivity state. All options from
  [Button](/components/button/#config-button).
- **get_trigger_speed** (*Optional*, button): Request trigger speed state. All options from
  [Button](/components/button/#config-button).
- **get_z_range** (*Optional*, button): Request Z-axis range. All options from
  [Button](/components/button/#config-button).
- **get_installation** (*Optional*, button): Request installation mode from the radar and update the
  `installation_mode` select with `top` or `side`. All options from
  [Button](/components/button/#config-button).
- **get_low_power_mode** (*Optional*, button): Request low power mode state. All options from
  [Button](/components/button/#config-button).
- **get_low_power_sleep_time** (*Optional*, button): Request low power sleep time. All options from
  [Button](/components/button/#config-button).
- **reset_unattended** (*Optional*, button): Reset the module's unattended (no-person) state used by its
  low-power logic. Helpful if the device gets stuck in an unattended state. All options from
  [Button](/components/button/#config-button).
- **clear_dwell** (*Optional*, button): Clear dwell areas and request updated area coordinates.
  All options from [Button](/components/button/#config-button).

### Reading the OUT Pin

Connect OUT / P20 to the input specified below. Set **P20 Mode** to `presence_high` for a high level
when presence is detected. This GPIO sensor reads the physical level, which follows the selected P20
mode independently of the UART target sensors. For `presence_low`, set `inverted: true` in the pin schema.

```yaml
binary_sensor:
  - platform: gpio
    pin: GPIOXX
    name: Radar OUT

select:
  - platform: ld6004
    p20_mode:
      name: P20 Mode
```
