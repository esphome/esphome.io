The TMP102 temperature sensor allows you to use [Texas Instruments TMP102](https://www.ti.com/product/TMP102)
and LM75 sensors with ESPHome. TMP102 breakout boards are available from
[SparkFun](https://www.sparkfun.com/products/13314). The [I²C Bus](/components/i2c/) must be configured first.

```yaml
# Example configuration entry
sensor:
  - platform: tmp102
    name: "Living Room Temperature"
    update_interval: 60s
```

## Configuration Variables

- **update_interval** (*Optional*, [Time](/guides/configuration-types/#time)): How often ESPHome reads the sensor.
  Defaults to `60s`.
- **address** (*Optional*, int): The I²C address. Defaults to `0x48`. TMP102 supports `0x48` through `0x4B`,
  selected by the ADD0 pin.
- All other options from [Sensor](/components/sensor/).

### Optional Hardware Settings

Existing temperature-only configurations work unchanged and do not write configuration or threshold registers
at startup.
Setting any option below enables hardware configuration.
ESPHome then writes the configuration register and both threshold registers during setup, using the defaults below
for omitted settings. These settings apply to TMP102 chips; do not enable them for LM75 sensors.

When hardware configuration is enabled, ESPHome checks the configuration and threshold registers before each update.
If they differ from the accepted settings, for example after a chip-only power reset, ESPHome restores them and skips
that update. A warning remains until a complete read succeeds. Do not use another controller to change these registers
while ESPHome manages them.

- **extended_mode** (*Optional*, boolean): Use the 13-bit temperature format.
  Defaults to `false` when configuring hardware.
- **conversion_rate** (*Optional*, string): Chip conversion rate: `0.25Hz`, `1Hz`, `4Hz`, or `8Hz`.
  Defaults to `4Hz` when configuring hardware. This is independent of `update_interval`.
- **one_shot_mode** (*Optional*, boolean): Keep the chip in shutdown between readings and trigger one conversion
  per update. Defaults to `false` when configuring hardware.
- **alert_polarity** (*Optional*, string): ALERT pin polarity, `active_low` or `active_high`.
  Defaults to `active_low` when configuring hardware.
- **thermostat_mode** (*Optional*, string): `comparator` or `interrupt`.
  Defaults to `comparator` when configuring hardware.
- **fault_queue** (*Optional*, int): Consecutive fault conversions required before ALERT changes: `1`, `2`, `4`, or `6`.
  Defaults to `1` when configuring hardware.
- **temperature_high** (*Optional*, temperature): Initial high threshold. Defaults to `80°C` when configuring hardware.
- **temperature_low** (*Optional*, temperature): Initial low threshold. Defaults to `75°C` when configuring hardware.

Thresholds accept Celsius or Fahrenheit values, such as `30°C` or `86°F`. The low threshold must not exceed the high
threshold. Supported thresholds range from `-55°C` to `127.9375°C` in normal mode, or `150°C` in extended mode.
The chip stores thresholds in steps of `0.0625°C`; values are rounded to the nearest step, with exact half-steps
rounded away from zero. Number states and saved values reflect the rounded hardware thresholds.
Temperature sensor filters do not change thermostat thresholds or alert decisions.

In continuous mode, the chip makes conversions independently of ESPHome polling. In one-shot mode, ESPHome waits
40 ms after triggering a conversion before reading it. Continuous-mode reads happen immediately and do not force
a new conversion. Very short update intervals do not restart a pending one-shot conversion. Each reading uses the
format flag in the temperature register, including when a sample still uses the previous mode's format.
