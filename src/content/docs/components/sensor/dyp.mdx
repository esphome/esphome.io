The `dyp_*` sensor platforms allow you to use UART-based ultrasonic distance sensors manufactured by [Shenzhen DYP Sensor Technology Co., Ltd](https://www.dypcn.com/ultrasonic-distance-sensor/) (and rebranded by vendors such as DFRobot and Adafruit) with ESPHome. Each series has its own platform (for example, `dyp_a01`, `dyp_a02`, `dyp_a13`, `dyp_me007ys`) built on a shared `dyp_base` driver.

These components support:

- **Automatic Modes:** Sensors that output distance frames continuously over UART.
- **Controlled Modes:** Sensors that require a trigger signal (via a GPIO pin or UART TX) before taking a measurement.
- **Processed vs Realtime:** Switching output filtering modes via a GPIO pin on supported hardware (**Automatic modes only**).

## Supported Series and Models

## Configuration variables

- **platform** (**Required**, string): The sensor series platform (`dyp_a01`, `dyp_a02`, `dyp_a06`, `dyp_a07`, `dyp_a08`, `dyp_a09`, `dyp_a10`, `dyp_a11`, `dyp_a12`, `dyp_a13`, `dyp_a15`, `dyp_a16`, `dyp_a17`, `dyp_a19`, `dyp_a20`, `dyp_a21`, `dyp_a22`, `dyp_a25`, `dyp_ds1603`, `dyp_l02`, `dyp_l07a`, `dyp_l08`, `dyp_me007ys`, or `dyp_r01`).
- **model** (**Required**, string): The specific model within the chosen series (e.g., `A01ANYUB`, `A02YYUW`, `A13NYTW`, `ME007YS`). Setting this configures the default `blind_zone`, `max_range`, required UART `baud_rate`, and operating `mode`.
- **uart_id** (*Optional*, [ID](/guides/configuration-types/#id)): The ID of the [UART Component](/components/uart/) to use. Required if more than one UART component exists; implied if only one exists.
- **mode** (*Optional*, string): Operating mode for configurable models (defaults to `AUTO`, or fixed by the model specification).
  - `AUTO`: The sensor sends data automatically.
  - `CONTROLLED`: ESPHome triggers the sensor to read data.
- **update_interval** (*Optional*, [Time](/guides/configuration-types/#time)): The interval to check the sensor. Defaults to `1s`.
  - In `CONTROLLED` mode: How often to trigger a reading.
  - In `AUTO` mode with `publish_mode: INTERVAL`: How often to publish the latest state.
  - In `AUTO` mode with `publish_mode: IMMEDIATE`: Ignored for publishing (data is pushed as each frame arrives).
- **blind_zone** (*Optional*, distance): Readings at or below this distance are reported as `unknown` (`NAN`). Defaults to the model's datasheet value and can be overridden if needed.
- **max_range** (*Optional*, distance): Readings above this distance are reported as `unknown` (`NAN`). Defaults to the model's datasheet value and can be overridden if needed.
- **trigger_pin** (*Optional*, [Pin Schema](/guides/configuration-types/#pin-schema)): The GPIO pin used to trigger a reading in `CONTROLLED` mode. If omitted in `CONTROLLED` mode, the component triggers via the UART `tx_pin` (common for models such as `A02YYT`).
- **output_mode** (*Optional*, string): For supported `AUTO` sensors, determines the data processing algorithm. Requires `output_mode_pin` to be configured.
  - `PROCESSED`: (Default when `output_mode_pin` is set) The sensor filters data for stability.
  - `REALTIME`: The sensor outputs raw, faster updates.
- **output_mode_pin** (*Optional*, [Pin Schema](/guides/configuration-types/#pin-schema)): The GPIO pin connected to the sensor's mode selection pin (usually the sensor's RX pin) to switch between `PROCESSED` (HIGH) and `REALTIME` (LOW). If you only need RX on the UART bus, omit `tx_pin` from the `uart:` configuration and specify that GPIO here as `output_mode_pin`.
- **publish_mode** (*Optional*, string): **Only applies when mode is AUTO.**
  - `INTERVAL`: (Default) The sensor is polled according to `update_interval`, and the latest reading (or `unknown` if no reading arrived or the reading was out of range) is published. Recommended for Home Assistant to prevent flooding.
  - `IMMEDIATE`: Every frame received from the UART is immediately published (reporting `unknown` if the reading is within `blind_zone` or exceeds `max_range`).
- All other options from [Sensor](/components/sensor/).

> [!NOTE]
> Compared to the standalone [A01NYUB](/components/sensor/a01nyub/) and [A02YYUW](/components/sensor/a02yyuw/) components (which publish every incoming UART frame at ~10 Hz, and in the case of `a02yyuw` report in millimeters), `dyp_a01` and `dyp_a02` report in meters (`m`) with `accuracy_decimals: 3` and default to `publish_mode: INTERVAL` with `update_interval: 1s`.

## Examples

### Simple Auto Sensor (`dyp_a02` / `A02YYUW`)

```yaml
uart:
  rx_pin: GPIO3
  baud_rate: 9600

sensor:
  - platform: dyp_a02
    model: A02YYUW
    name: "Water Level"
    update_interval: 60s
```

### Controlled Sensor (`dyp_a02` / `A02YYT`)

The `A02YYT` requires a trigger signal. By connecting the sensor's RX pin to the ESP's TX pin, this component triggers readings over UART:

```yaml
uart:
  tx_pin: GPIO1
  rx_pin: GPIO3
  baud_rate: 9600

sensor:
  - platform: dyp_a02
    model: A02YYT
    name: "Oil Tank Level"
    update_interval: 10s
```

### Overriding `blind_zone` or `max_range`

Each model sets `blind_zone` and `max_range` from its datasheet, but you can override either parameter if your installation requires custom bounds:

```yaml
uart:
  tx_pin: GPIO17
  rx_pin: GPIO16
  baud_rate: 9600

sensor:
  - platform: dyp_a13
    model: A13NYTW
    name: "Tank Distance"
    blind_zone: 20cm
    max_range: 180cm
    update_interval: 5s
```

### Sump Pit Level (Advanced Calculation)

In this example, we calculate the depth of water in a sump pit using a `dyp_a13` sensor (`model: A13NYTW`). The sensor returns the "air gap" (distance from sensor to water), so we subtract that from the total depth of the pit to get the water level:

```yaml
sensor:
  - platform: dyp_a13
    name: "Sump Pit Water Depth"
    model: A13NYTW
    update_interval: 5s
    unit_of_measurement: "in"
    icon: "mdi:waves"
    accuracy_decimals: 2
    filters:
      # Filter noise by taking the median of the last 6 readings
      - median:
          window_size: 6
          send_every: 6
          send_first_at: 6
      # Convert "Distance to Water" (Air Gap) into "Depth of Water"
      - lambda: |-
          // x is the sensor reading in meters (e.g., 0.5m)
          // 1. Convert meters to inches
          float air_gap_inches = x * 39.3701;

          // 2. Define physical constants
          float total_pit_depth = 72.0;
          float sensor_offset = 3.0; // Mounting height or enclosure offset

          // 3. Calculate water depth: (Total Depth - Offset) - Air Gap
          return (total_pit_depth - sensor_offset) - air_gap_inches;
```
