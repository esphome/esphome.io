---
title: "VL6180X Time Of Flight Sensor"
description: "Configure VL6180X time of flight distance and ambient light sensors in ESPHome."
---

The `vl6180x` component uses the ST VL6180X time of flight sensor to measure distance and ambient light over I²C.
It supports multiple sensors on one I²C bus, optional interrupt and XSHUT/CE pins, and automatic recovery after
communication failures.

The [I²C Bus](/components/i2c/) must be configured for this component.

```yaml
i2c:
  sda: GPIOXX
  scl: GPIOXX

vl6180x:
  - id: tof_sensor

sensor:
  - platform: vl6180x
    vl6180x_id: tof_sensor
    range:
      name: "Distance"
    lux:
      name: "Illuminance"

text_sensor:
  - platform: vl6180x
    vl6180x_id: tof_sensor
    range_status:
      name: "Range status"
```

The sensor's default I²C address is `0x29`. A VL6180X sensor provides distance and ambient light measurements. If your
module contains a VL6180 variant without ambient light sensing, omit the `lux` section from the sensor platform.

## Wiring

- `VCC` connects to the voltage supported by your sensor breakout board.
- `GND` connects to ground.
- `SCL` connects to I²C SCL.
- `SDA` connects to I²C SDA.
- `GPIO1` is the optional interrupt output. Connect it to `interrupt_pin` to reduce I²C polling while a measurement is
  in progress.
- `XSHUT` or `CE` is the optional sensor enable input. Connect it to `enable_pin` when using multiple sensors or a
  non-default I²C address.

## Configuration Variables

- **id** (*Optional*, ID): The component instance ID. ESPHome generates an ID if one is not provided.
- **address** (*Optional*, int): The sensor I²C address. Defaults to `0x29`. Each sensor on the same bus must have a
  unique address. A non-default address requires `enable_pin` so the component can assign the address at startup.
- **update_interval** (*Optional*, [Time](/guides/configuration-types/#time)): The interval between distance updates.
  Defaults to `60s`.
- **enable_pin** (*Optional*, [Pin Schema](/guides/configuration-types/#pin-schema)): The GPIO connected to the
  sensor's XSHUT/CE input. Required for every sensor when more than one sensor is configured, and required when using a
  non-default I²C address. Each sensor needs its own pin.
- **interrupt_pin** (*Optional*, [GPIO Pin Schema](/guides/configuration-types/#pin-schema)): The GPIO connected to the
  sensor's interrupt output. When omitted, the component polls the sensor over I²C.
- **recovery** (*Optional*): Automatic recovery settings.
  - **failure_threshold** (*Optional*, int): Consecutive measurement or I²C failures before recovery starts. Defaults
    to `3`.
  - **retry_interval** (*Optional*, [Time](/guides/configuration-types/#time)): Delay between recovery attempts.
    Defaults to `30s`.
  - **max_retries** (*Optional*, int): Number of recovery attempts before the component increases the retry delay.
    Defaults to `10`. Recovery continues after this limit with a delay of at least `30s`.

## Sensor Platform

Configure distance and ambient light entities under `sensor:` and reference the `vl6180x` hub with `vl6180x_id`. Put
both optional entities in one platform entry. At least one of `range` or `lux` is required.

- **range** (*Optional*): Distance sensor. **scaler** (*Optional*, int) supports `1` to `3` and defaults to `1`.
  Higher values increase the reported measurement range; distance is reported in millimeters. All other options from
  [Sensor](/components/sensor/) are supported.
- **lux** (*Optional*): Ambient light sensor. **gain** (*Optional*, float) supports `1`, `1.25`, `1.67`, `2.5`, `5`,
  `10`, `20`, or `40`, and defaults to `1`. **update_interval** (*Optional*, [Time](/guides/configuration-types/#time))
  controls its measurement interval and defaults to the hub's `update_interval`. All other options from
  [Sensor](/components/sensor/) are supported.

## Text Sensor Platform

To publish the range result, add a `text_sensor:` entry with `platform: vl6180x`, the hub's `vl6180x_id`, and a
`range_status` sensor. It reports values such as `OK`, `No Target`, `Out of Range`, and `Sensor Error`. All standard
options from [Text Sensor](/components/text_sensor/) are supported.

## Multiple Sensors

Each sensor on the same I²C bus needs a unique address and its own `enable_pin`. The component uses the enable pins to
initialize sensors one at a time, preventing their default `0x29` addresses from colliding during startup.

```yaml
vl6180x:
  - id: near_sensor
    address: 0x29
    enable_pin: GPIOXX

  - id: far_sensor
    address: 0x30
    enable_pin: GPIOXX

sensor:
  - platform: vl6180x
    vl6180x_id: near_sensor
    range:
      name: "Near Distance"
  - platform: vl6180x
    vl6180x_id: far_sensor
    range:
      name: "Far Distance"
```

Choose GPIOs supported by your board and connect each one to the corresponding sensor's XSHUT/CE pin. Do not use the
same `enable_pin` for multiple sensors.

## Non-Blocking Measurements and Recovery

Measurements advance through short I²C operations in the ESPHome loop, so the component does not wait synchronously for
a measurement to finish. If `interrupt_pin` is configured, its signal indicates when a result is ready; otherwise the
component polls the sensor status over I²C.

After the configured number of consecutive communication or measurement failures, the component reinitializes the
sensor or sensor group. If recovery attempts continue to fail, the component increases the retry delay after
`max_retries` attempts and keeps trying.
