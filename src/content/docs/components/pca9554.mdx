The PCA9554 component allows you to use a variety of I/O expanders in ESPHome that use the [I²C Bus](/components/i2c) 
for communication. Once configured, you can use any of the IO pins (up to 16) with your projects. Within ESPHome they 
emulate a real internal GPIO pin and can therefore be used with many of ESPHome's components such as the GPIO
binary sensor or GPIO switch. Any option accepting a [Pin Schema](/guides/configuration-types#pin-schema) can theoretically
be used, but some more complicated components that do communication through this I/O expander will not work.

## Tested devices

The following devices have been tested with this component and can be used by setting the `device` in your YAML.

| Device    | Number of Pins | I2C Address | Features |
| ---       | ---            | ---         | I/O |
| PCA9554   | 8              | 0x20-0x27   | I/O |
| PCA9554A  | 8              | 0x38-0x3F   | I/O |
| PCA9536   | 4              | 0x41        | I/O |
| PCA9535   | 16             | 0x20-0x27   | I/O |
| PCAL9538A | 8              | 0x70-0x73   | I/O, Pull Up/Down, Open Drain Outputs, Latching, Maskable Interrupt, Variable Drive Strength |
| PCAL9555A | 16             | 0x20-0x27   | I/O, Pull Up/Down, Open Drain Outputs, Latching, Maskable Interrupt, Variable Drive Strength |

Devices that show a range of I2C addresses have an address that can be set using strapping pins on the device.

Other I/O expanders that use this command interface and up to 16 I/O pins should also work.
 * TCA9554
 * TCA9535
If these devices have the same number of pins and features as the supported devices above, you can use that device
name in your YAML. For many of the devices with different part numbers, the only change is the I2C address range,
which can be set independently of the device type.

```yaml
# Example configuration entry
pca9554:
  - id: "setup_expander"
    address: 0x70
    device: PCAL9554

# Individual outputs
switch:
  - platform: gpio
    name: "PCAL9554 Pin 2"
    pin:
      pca9554: setup_expander
      number: 2
      mode:
        output: true

binary_sensor:
  - platform: gpio
    name: "PCAL9554 Pin 3"
    pin:
      pca9554: setup_expander
      number: 3
      mode:
        input: true
        pullup: true
        pulldown: false
        latch: false
        interrupt: false
```

## Configuration variables

- **id** (**Required**, [ID](/guides/configuration-types#id)): The id to use for this `pca9554` component.
- **address** (*Optional*, int): The I²C address of the driver. This is technically optional, but you should 
  really check to make sure you have the right address as the default will not work for many of the supported components.
  Defaults to `0x20`.

- **device** (*Optional*, string): When using a supported device, you may set the device name per the above table.
  If this is not set, it will default to 'NONE' and the `pin_count` below needs to be set.

- **pin_count** (*Optional*, int): The number of bits implemented in the expander. If you set the device type above,
  do not set this variable.

> [!NOTE]
> If you define the device using pin_count, you **must** set pin_count to the total number of pins on the device.

## Pin configuration variables

- **pca9554** (**Required**, [ID](/guides/configuration-types#id)): The id of the `pca9554` component of the pin.
- **number** (**Required**, int): The pin number.
- **inverted** (*Optional*, boolean): If all read and written values
  should be treated as inverted. Defaults to `false`.

- **mode** (*Optional*, boolean(s)): Pin mode settings for the selected pin. Multiple pin modes may be selected by
  indenting them after the `mode:` entry in the YAML as shown in the example above. All devices support `input` and `output`. 
  The PCAL series devices additionaly support `pullup`, `pulldown`, `latch`, and `interrupt`.

## Description of the mode settings

###input
Define the device as a high impedance input.

###output
Define the device as a push/pull output

###pullup
If the pin is configured as an `input` enable a 100K pull up.

###pulldown
If the pin is configured as an `input` enable a 100K pull down.

###latch
If the pin is configured as an `input`, latch the input. With this enabled, if the input changes state, the pin state will be latched
at the new level, and will not change, even if the pin goes back to its original state. This latch is cleared when the pin state 
register is read. This is likley only useful if you are trying to detect *very* fast transient signals.

###interrupt
If the pin is configured as an `input`, enable interrupt generation on this pin. If this option is enabled, any level change on the pin
will cause the interrupt pin on the device to pull low. If this pin is monitored by the main CPU, it can be used to asynchronously detect
pin changes.
