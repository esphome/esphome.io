The M-Bus component creates an M-Bus connection to control an M-Bus slave device, letting your ESPHome node act as an M-Bus master.
You can access registers from your M-Bus slave device as sensors and present them to your favorite home automation system.

This is a partial port of the [libmbus](https://github.com/rscada/libmbus/tree/master) library.
More details about the M-Bus Protocol can be found here: [M-Bus specification](https://m-bus.com/documentation)

## Hardware setup

M-Bus does not work with TTL-level signaling.
You need a TTL-to-M-Bus master module:

![M-Bus TTL master module](/images/mbus-master-module.png)

The transceiver connects to the UART of the MCU. For ESP32, pin 16 to TXD and pin 17 to RXD are common defaults, but other pins can also be used.
You must connect 3.3V to TTLVCC, at least 5V to VIN, and GND to GND.
The M-Bus Clients are connected to M+.

This module converts TTL Levels to Voltage and Current signals and provides the necessary power supply (+36V).

## Configuration variables for M-Bus Component

- **mbus_id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID of the mbus master.
- **secondary_address** (*Optional*): The secondary address of the M-Bus slave.
- **interval** (*Optional*, [Time](/guides/configuration-types#time)): Interval of the command loop for reading M-Bus slaves (default: `1min`).

## Configuration variables for M-Bus Sensor

- **mbus_id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID of the mbus master.
- **data_index** (**Required**): Index of the data in the M-Bus Client response. Index is 0 based.
- **factor** (*Optional*): Divider for scaling the reading (default: `1.0`). The value is divided by the factor before being published to Home Assistant.

## Operation Modes

If no secondary_address is set, the M-Bus Component starts to discover the connected Slaves in the M-Bus Network and prints the detected slave addresses to the log.

> [!NOTE]
> You have to set the logger level to at least DEBUG to see the detected slave addresses.

If `secondary_address` is set, the M-Bus component starts the readout loop.

## Example

The following code creates an M-Bus master and a sensor definition to read the first data frame.

```yaml
    logger:
      tx_buffer_size: 1024
      level: DEBUG

    uart:
      id: m_bus
      baud_rate: 2400
      data_bits: 8
      parity: EVEN
      stop_bits: 1
      rx_pin: 16
      tx_pin: 17

    mbus:
      secondary_address: 0x0025426642042002
      interval: "5s"
      sensor:
        - data_index: 0
          factor: 10
          name: "Energy Consumption"
          accuracy_decimals: 1
          device_class: energy
          icon: "mdi:flash"
          state_class: total_increasing
          unit_of_measurement: "Wh"
```

  - Type: Data type of the value.

## Known Limitations

- Slave discovery may not work if the secondary address starts with a value not equal to 0 due to the fixed discovery mask.
- All code is tested with an M-Bus network with one slave and may not work if multiple slaves are connected.
- Only BCD, Integer and Float values are supported.
- Custom Data is not supported.
