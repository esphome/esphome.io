The `epaper_spi` display platform provides a new ePaper display component architecture
with improved state management and non-blocking operation. This component implements a
queue-based state machine that eliminates blocking waits for the busy pin and provides
better integration with ESPHome's async architecture.

The communication method uses [SPI](/components/spi), so you need to have an `spi:` section in your
configuration.

The driver supports a number of displays and there are also specific configurations for ESP32 boards with integrated displays.
For those boards the predefined configuration will set the correct pins and dimensions for the display.

```yaml
display:
  - platform: epaper_spi
    model: Seeed-reTerminal-E1002
    lambda: |-
      it.filled_circle(it.get_width() / 2, it.get_height() / 2, 50, Color::BLACK);
```

## Configuration variables

When using a model defining an integrated display board most of the configuration such as the pins and dimensions will be set by default,
but can be overridden if needed.

- **model** (**Required**): The model of the ePaper display. See the table above for options (case is not significant).
- **cs_pin** (**Required**, [Pin Schema](/guides/configuration-types#pin-schema)): The CS pin. Predefined for integrated boards.
- **cs1_pin** (*Optional*, [Pin Schema](/guides/configuration-types#pin-schema)): The secondary CS pin for dual-CS displays (e.g. T133A01). Predefined for integrated boards that require it.
- **dc_pin** (**Required**, [Pin Schema](/guides/configuration-types#pin-schema)): The DC pin. Predefined for integrated boards.
- **busy_pin** (*Optional*, [Pin Schema](/guides/configuration-types#pin-schema)): The BUSY pin, if used. Required for
  `GooDisplay-GDEY029Z95-2.9`.

  > [!NOTE]
  > Some displays use inverted busy pin polarity (LOW = busy, HIGH = idle). For these models, set `inverted: true`
  > on the busy pin. This applies to: `UC8151`, `Waveshare-1.54in-G`, `Waveshare-2.13in-bv3`, `Waveshare-2.13in-G`,
  > `Waveshare-2.13in-G-V1`, `Waveshare-7.5in-H`, `Waveshare-7.5in-V2`, `inkplate6color`.

- **reset_pin** (*Optional*, [Pin Schema](/guides/configuration-types#pin-schema)): The RESET pin, if used. Required for the SSD1681-based models (`SSD1681`, `Waveshare-1.54in-v2`, `GooDisplay-GDEY0154D67-1.54`), whose panels only wake from deep sleep on a hardware reset, and for `GooDisplay-GDEY029Z95-2.9`.
  Make sure you pull this pin high (by connecting it to 3.3V with a resistor) if not connected to a GPIO pin.
- **enable_pin** (*Optional*, [Pin Schema](/guides/configuration-types#pin-schema)): An optional pin to enable the
  display, if required. A list of pins can be provided for displays that require multiple enable pins.
  A full pin configuration may be provided to set the pin mode and inverted property if required.
  The pin or pins will be driven high (low if inverted) prior to display initialisation.
  If `enable_pin` is not set, the model's default enable pins are used, if it has any. A default enable pin
  that is also used elsewhere in the configuration, for example by a GPIO switch, is left out, so you can
  control that pin yourself. If every other use of the pin sets `allow_other_uses: true`, the pin is shared
  with the display instead. Setting `enable_pin` replaces all of the model's default enable pins.
- **dimensions** (**Required**, dict): Dimensions of the screen, specified either as *width* **x** *height* (e.g `320x240`  )
  or with separate config keys. For integrated boards with full pre-defined configuration this is optional and will be preset by
  the model selected. The dimensions are specified in pixels, and the width and height must be greater than 0.

  > [!NOTE]
  > `Waveshare-2.13in-G` and `Waveshare-2.13in-G-V1` declare a width of 124 and 128 for a 122 pixel panel, because
  > their init sequence fixes the controller's row length at that value and the buffer has to match it. `get_width()`
  > returns the padded width; the hidden columns are the last ones of each row in the panel's native orientation,
  > so content anchored at the left edge is fully visible and lambdas should treat 122 as the visible width. Do not
  > override `dimensions` on these models: the row length in the init sequence does not follow it and the image
  > shears diagonally.

  - **height** (**Required**, int): Specifies height of display.
  - **width** (**Required**, int): Specifies width of display.
  - **offset_height** (*Optional*, int): Only for UC8279 models. The number of rows the controller scans before the
    panel's first row. The panel is bonded to the last rows of the controller's gates, so a panel that does not start
    at the first gate needs this set to its offset. Defaults to `0`, or the panel's own offset for a predefined model
    such as `Xteink-X4Pro-UC8279`.

- **rotation** (*Optional*, int): Set the rotation of the display. Everything you draw in `lambda:` will be rotated
  by this option. One of `0°` (default), `90°`, `180°`, `270°`.
- **transform** (*Optional*, dict): If `rotation` is not sufficient, use this to transform the display. Options are:
  - **mirror_x** (**Required**, boolean): If true, mirror the x axis.
  - **mirror_y** (**Required**, boolean): If true, mirror the y axis.

- **reset_duration** (*Optional*, [Time](/guides/configuration-types#time)): Duration for the display reset operation. Defaults to `200ms`.
- **lambda** (*Optional*, [lambda](/automations/templates#config-lambda)): The lambda to use for rendering the content on the display.
  See [Display Rendering Engine](/components/display#display-engine) for more information.
- **pages** (*Optional*, list): Show pages instead of a single lambda. See [Display Pages](/components/display#display-pages).
- **update_interval** (*Optional*, [Time](/guides/configuration-types#time)): The interval to re-draw the screen. Defaults to `60s`,
  use `never` to only manually update the screen via `component.update`.
- **full_update_every** (*Optional*, int): On screens that support partial updates, this sets the number of updates
  before a full update is forced. Defaults to `1` which will make every update a full update. A full update can also be
  requested at any time with the [`epaper_spi.full_update_next`](#epaper_spi-full_update_next-action) action.
- **monochrome_partial_updates** (*Optional*, boolean): Only for four-level grayscale models
  (`Seeed-reTerminal-Sticky-gray4`). Allows `full_update_every` greater than `1`, with the partial updates in between
  in black and white. Defaults to `false`: every update is a full four-level update. See
  [Four-level grayscale](#four-level-grayscale-reterminal-sticky) for the trade-off this accepts.
- **border_waveform** (*Optional*, int): Only for SSD1677 models. The border waveform byte (controller command `0x3C`),
  which sets how the border around the active area is driven. Defaults to `0x01`, or `0x00` for
  `Seeed-reTerminal-Sticky-gray4`. Rarely needs changing.
- **spi_id** (*Optional*, [ID](/guides/configuration-types#id)): Required to specify the ID of the [SPI Component](/components/spi) if your
  configuration defines multiple SPI buses. If only a single SPI bus is configured, this is optional.
- **id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID used for code generation.

### Full configuration example

```yaml
display:
  - platform: epaper_spi
    model: SSD1677
    full_update_every: 10
    update_interval: 5s
    dimensions:
      width: 800
      height: 480
    transform:
      mirror_x: true
      mirror_y: false
    rotation: 90 # Rotate to portrait
    cs_pin: GPIOXX
    dc_pin: GPIOXX
    reset_pin: GPIOXX
    busy_pin: { number: GPIOXX, inverted: False, mode: { input: True, pulldown: True } }
```

### Fast and partial refresh example (reTerminal E1001)

Displays based on the UC8179 controller (`Waveshare-7.5in-V2`, `Seeed-reTerminal-E1001`) support fast full and
partial refresh. Set `full_update_every` greater than `1` to enable it: a fast full refresh is performed every
`full_update_every` updates, with partial refreshes in between. With the default of `1`, every update is a normal
full refresh.

```yaml
display:
  - platform: epaper_spi
    model: Seeed-reTerminal-E1001
    update_interval: 30s
    full_update_every: 30
    lambda: |-
      it.filled_circle(it.get_width() / 2, it.get_height() / 2, 50, Color::BLACK);
```

### Partial refresh example (1.54" SSD1681 panels)

The 200x200 panels based on the SSD1681 (`Waveshare-1.54in-v2`, `GooDisplay-GDEY0154D67-1.54`, or `SSD1681` for
another panel of that size) support partial refresh. Set `full_update_every` greater than `1` to enable it: only the
pixels that changed since the previous update are driven, so a partial refresh is quick and does not flash the
panel. The full refresh every `full_update_every` updates clears any residue.

The panel is put into deep sleep after every update and only a hardware reset wakes it, so `reset_pin` is required.

> [!NOTE]
> Partial refresh relies on a setting the panel maker stores in the controller (RAM ping-pong), which both named
> panels have. If the generic `SSD1681` model gives garbled partial updates on another panel, that panel lacks it;
> leave `full_update_every` at `1`.

This example assumes a [font](/components/font/) with id `my_font` and a [time source](/components/time/) with id `my_time`.

```yaml
display:
  - platform: epaper_spi
    model: Waveshare-1.54in-v2
    cs_pin: GPIOXX
    dc_pin: GPIOXX
    reset_pin: GPIOXX
    busy_pin: GPIOXX
    update_interval: 60s
    full_update_every: 20
    lambda: |-
      it.strftime(0, 0, id(my_font), Color::BLACK, "%H:%M", id(my_time).now());
```

### Four-Level Grayscale (reTerminal Sticky)

The `Seeed-reTerminal-Sticky-gray4` model drives the panel in four gray levels. With `monochrome_partial_updates: true`,
`full_update_every` can be greater than `1`, and the partial updates in between are black and white. The first partial
update removes the gray levels from the whole panel until the next full update, a trade-off often worth making for the
noticeably sharper text.

In this mode, an update is partial by default; request a full one with
[`epaper_spi.full_update_next`](#epaper_spi-full_update_next-action) to bring the gray levels back:

```yaml
display:
  - platform: epaper_spi
    id: epaper
    model: Seeed-reTerminal-Sticky-gray4
    monochrome_partial_updates: true
    full_update_every: 30
```

```yaml
# Partial update: fast, black and white
on_...:
  - component.update: epaper

# Full four-level update, bringing the gray levels back
on_...:
  - epaper_spi.full_update_next: epaper
  - component.update: epaper
```

> [!NOTE]
> With custom `dimensions`, the width must be a multiple of 8.

### 4-color display example

Some displays support 4 colors (black, white, red, yellow). Colors are mapped from RGB automatically; see
[Color Panels](#color-panels).
Full refresh times for 4-color displays are typically around 20 seconds.

```yaml
spi:
  clk_pin: GPIO13
  mosi_pin: GPIO14

display:
  - platform: epaper_spi
    model: Waveshare-7.5in-H
    cs_pin: GPIO15
    dc_pin: GPIO27
    reset_pin: GPIO26
    busy_pin:
      number: GPIO25
      inverted: true
    update_interval: 5min
    lambda: |-
      auto RED = Color(255, 0, 0);
      auto YELLOW = Color(255, 255, 0);

      it.filled_rectangle(50, 50, 80, 80, Color::BLACK);
      it.filled_rectangle(150, 50, 80, 80, RED);
      it.filled_rectangle(250, 50, 80, 80, YELLOW);
```

## Colors

### Background and Default Color

Most displays clear to black, but `epaper_spi` clears the display to white, like blank paper. This applies to the
automatic clear before each update (see `auto_clear_enabled` in [Display](/components/display/)) and to `it.clear()`.

Drawing methods called without a color still draw in `Color::WHITE`, which on this display is white on white, so
nothing appears. The same applies to `graph()`, `legend()` and `qr_code()`. Pass a color explicitly:

```yaml
display:
  - platform: epaper_spi
    # ...
    lambda: |-
      it.line(0, 0, 50, 50, Color::BLACK);
      it.print(0, 10, id(my_font), Color::BLACK, "Hello World!");
```

Antialiased fonts (`bpp` greater than `1`) blend the edges of each character with a background color that defaults to
`Color::BLACK`, so on white paper the edges come out darker than intended. Pass `Color::WHITE` as the background:

```yaml
display:
  - platform: epaper_spi
    # ...
    lambda: |-
      it.print(0, 10, id(my_font), Color::BLACK, TextAlign::TOP_LEFT, "Hello World!", Color::WHITE);
```

### Black and White and Grayscale Panels

Black and white panels convert each color to black or white by its brightness (luma), calculated with the Rec.601
weights, which count green far more than red or blue:

$$
Y = 0.299R + 0.587G + 0.114B
$$

A luma of `128` or more draws white, anything lower draws black. The four-level grayscale model
(`Seeed-reTerminal-Sticky-gray4`) uses the same luma, split into four bands: below `32` draws black, `32` to `95` dark
gray, `96` to `159` light gray, and `160` or more white.

Saturated colors therefore do not map the way their RGB values might suggest:

| Color                  | Luma | Black and white | Four-level gray |
|------------------------|------|-----------------|-----------------|
| Red `(255, 0, 0)`      | 77   | Black           | Dark gray       |
| Green `(0, 255, 0)`    | 149  | White           | Light gray      |
| Blue `(0, 0, 255)`     | 29   | Black           | Black           |
| Yellow `(255, 255, 0)` | 226  | White           | White           |
| Cyan `(0, 255, 255)`   | 178  | White           | White           |
| Magenta `(255, 0, 255)`| 106  | Black           | Light gray      |
| Orange `(255, 165, 0)` | 173  | White           | White           |
| Gray `(128, 128, 128)` | 128  | White           | Light gray      |
| Gray `(127, 127, 127)` | 127  | Black           | Light gray      |

This has some consequences:

- Green, yellow, cyan and orange draw white, so they are invisible on the white background.
- Red, blue and magenta draw black, so they cannot be told apart from black, for example to highlight a warning.
- A darker green such as `Color(0, 200, 0)` (luma 117) draws black, while full green draws white.
- Mid grays flip between black and white at `128`, so a small change in a gray value can invert it.
- Images and LVGL content are converted pixel by pixel in the same way, without dithering, so areas of similar
  brightness become solid black or white. For photos, use a `BINARY` [image](/components/image/) with
  `dither: FLOYDSTEINBERG`, which keeps the shading.

### Color Panels

Panels with colored inks map each color to one of their inks. The `inkplate2`, 4-color (JD79660), 6-color
(`Seeed-reTerminal-E1002`, `Seeed-reTerminal-E1004`) and `inkplate6color` models first check whether the color is
close to gray, meaning its largest and smallest RGB components differ by less than `50`. A gray is drawn black or
white by its luma, as above (`Seeed-reTerminal-E1004` uses the plain average of the components instead). Any other
color counts each component as on above `128`, and the combination of components that are on selects the ink. Colors
with no matching ink are folded into another, and a dark color with no component above `128` is black.

The `WeAct-*-3c`, `Waveshare-2.13in-bv4`, `Waveshare-2.66in-b` and `Waveshare-7.5in-bV2-BWR` models use a simpler
rule: red if the red component is above `127` and greater than green and blue together, otherwise white if the average
of the components is at least half brightness, otherwise black.

| Color                  | WeAct and Waveshare 3-color | `inkplate2` | 4-color | 6-color | `inkplate6color` |
|------------------------|-----------------------------|-------------|---------|---------|------------------|
| Red `(255, 0, 0)`      | Red                         | Red         | Red     | Red     | Red              |
| Green `(0, 255, 0)`    | Black                       | Black       | Black   | Green   | Green            |
| Blue `(0, 0, 255)`     | Black                       | Black       | Black   | Blue    | Blue             |
| Yellow `(255, 255, 0)` | White                       | White       | Yellow  | Yellow  | Yellow           |
| Cyan `(0, 255, 255)`   | White                       | White       | White   | Green   | Green            |
| Magenta `(255, 0, 255)`| White                       | White       | White   | Red     | Red              |
| Orange `(255, 165, 0)` | Red                         | White       | Yellow  | Yellow  | Orange           |

Things to watch for:

- Magenta draws white on 3-color and 4-color panels, and so is invisible on the white background.
- Green draws black on 3-color and 4-color panels, but white on black and white panels.
- Orange draws red, white, yellow or orange depending on the panel.
- Yellow and cyan draw white on 3-color panels.

## Actions

### `epaper_spi.full_update_next` Action

Make the next update of the display a full one. That update refreshes the whole
panel, even if nothing new was drawn.

```yaml
on_...:
  - epaper_spi.full_update_next: epaper
  - component.update: epaper  # not needed if something else, such as LVGL, triggers the update
```

## Conditions

### `epaper_spi.is_updating` Condition

This condition lets automations check whether a display update or refresh is in progress. It is true from the moment an
update starts until the panel has finished refreshing and gone back to deep sleep.

```yaml
interval:
  - interval: 10s
    then:
      - if:
          condition:
            not:
              epaper_spi.is_updating: my_display
          then:
            - component.update: my_display
```

Configuration variables:

- **id** (**Required**, [ID](/guides/configuration-types#id)): The ID of the `epaper_spi` display.
