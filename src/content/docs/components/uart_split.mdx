The `uart_split` component reads one [UART bus](/components/uart/) and copies every received byte to each of its
outputs. Another component uses an output as its `uart_id`. An output has the baud rate, data bits, parity and stop
bits of the UART bus, and a component that requires certain settings is checked against those. Settings changed on an
output at runtime do not reach the pins: `load_settings()` on an output logs a warning and restores those of the UART
bus.

```yaml
# Example configuration entry
uart_split:
  - uart_id: uart_bus
    outputs:
      - id: bus
      - id: tap
        rx_only: true
```

`bus` reads and writes the pins. `tap` is receive-only. When `direction` is omitted, a receive-only output uses
`BOTH`, so it also receives what the other outputs send. Point a [Modbus](/components/modbus/) hub at `bus` and
a [UART TCP](/components/uart_tcp/) server at `tap` to publish that copy.

> [!NOTE]
> Another component on the same UART is rejected, and so is `dummy_receiver` in its `debug` options. This component
> has to be the only reader. Use an output instead. The check does not see a `uart.write` action or a lambda that
> uses the UART bus by its ID: a lambda that reads it takes bytes from the outputs, and bytes written there are not
> copied to `BOTH` outputs. Point those at an output as well.

> [!NOTE]
> More than one output may write. Those bytes share one transmit line.

Each output buffers up to 256 received bytes. The UART bus is read in the main loop, up to 256 bytes per pass.

When an output that writes is full, new bytes wait in the receive buffer of the UART bus, so the output loses
nothing. Once that buffer is half full, the output drops what does not fit, a warning is logged, and the other
outputs keep receiving. After the output has been read empty, bytes wait for it again. A larger `rx_buffer_size`
on the UART bus gives a slow output more time. A receive-only output drops bytes when it is full and never makes
bytes wait.

## Configuration Variables

- **id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID used for code generation.
- **uart_id** (**Required**, [ID](/guides/configuration-types#id)): The [UART bus](/components/uart/) to read.
  Baud rate, data bits, parity and stop bits are set there.
- **outputs** (**Required**, list): One to eight outputs. Each output is itself a UART. See
  [Output Configuration](#output-configuration).

## Output Configuration

- **id** (*Optional*, [ID](/guides/configuration-types#id)): An ID to assign to this output. Use it as `uart_id`
  in another component. ESPHome assigns one when it is omitted.
- **rx_only** (*Optional*, boolean): Drop bytes written to this output. A component that requires a TX pin, such
  as [DFPlayer](/components/dfplayer/), is rejected on it. Defaults to `false`.
- **direction** (*Optional*, string): `RX` or `BOTH`. `RX` copies only the bytes from the pins. `BOTH` also
  copies what the other outputs send. When `rx_only` is `true` and `direction` is omitted, the direction is
  `BOTH`. Otherwise it is `RX`.
- **debug** (*Optional*): Log the bytes this output receives and sends. Same options as the
  [UART debug](/components/uart/#debugging) option.
