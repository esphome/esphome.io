The `tcp_uart` component is a [UART bus](/components/uart/) whose other end is a TCP client. Bytes are copied
unchanged. Any component that takes a `uart_id` can use the socket the same way it uses a hardware UART.

The socket is not clocked, so this component has no baud rate.

```yaml
# Example configuration entry
tcp_uart:
  - id: remote_serial
    host: 192.0.2.10
    port: 502

modbus:
  - id: bus
    uart_id: remote_serial
```

## Configuration variables

- **id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID for this component. Other
  components use this ID as their `uart_id`.
- **host** (**Required**, string): The host to connect to. An IPv4 address. On the ESP32 a hostname is resolved as
  well.
- **port** (**Required**, int): The TCP port of the remote host.
- **reconnect_interval** (*Optional*, [Time](/guides/configuration-types#time)): How long to wait before connecting
  again after a failure. Defaults to `5s`.
- **connected** (*Optional*): A [binary sensor](/components/binary_sensor/) that is on while the TCP connection is
  up. It uses the diagnostic entity category and the connectivity device class.
