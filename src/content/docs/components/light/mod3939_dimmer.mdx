"Module 39x39" dimmers are a generic type of in-wall, brightness-only light dimming devices sold with Tuya-Smart application support,
yet using different method to control light than the already-supported [Tuya light](/components/light/tuya).

The devices are sold under different marketing names such as OXT, Smart Best, Himojo, HaveDeer, GIRIER, RSH, AVATTO which seem compatible
as well but have not been tested. All of them look identical and have same dimensions 39.2×39.2×18mm, thus it is very likely they are
using same hardware design and protocol. Hence the component name, "Module 39x39", as their dimension is what they all have in common.

> [!NOTE]
> Advantage of this implementation is that, unlike [Tuya](/components/light/tuya)-based devices, here the firmware has 
> full control over dimming functionality and physical switch input, so can control timings, transitions, effects, etc.

<Image src={mod3939UiImg} layout="constrained" alt="" />

There are two types of them, supporting either 1- or 2- light channels. For a 2-channel dimmer use config like below:

```yaml
# Example configuration entry
bk72xx:
  board: cb3s # Using original CB3S module by Tuya, can also be replaced with other pin-compatible

# Disable UART logging
logger:
  baud_rate: 0

uart: # rx_pin is not required (not used)
  tx_pin: GPIO11 # fixed
  baud_rate: 9600 # fixed

light:
  - platform: mod3939_dimmer
    channels:
      - name: "Light L1"
        id: dimmer1
        min_value: 0
        max_value: 255
      - name: "Light L2"
        id: dimmer2
        min_value: 0
        max_value: 255

binary_sensor:
  - platform: gpio
    id: terminal_s1
    pin:
      number: GPIO08 # hardwired
      mode:
        input: true
        pullup: true
      inverted: true
    on_press:
      - light.turn_on: dimmer1
    on_release:
      - light.turn_off: dimmer1

  - platform: gpio
    id: terminal_s2
    pin:
      number: GPIO09 # hardwired
      mode:
        input: true
        pullup: true
      inverted: true
    on_press:
      - light.turn_on: dimmer2
    on_release:
      - light.turn_off: dimmer2
```

For a 1-channel dimmer omit the second channel from the `mod3939_dimmer` configuration.

## Configuration variables

- **channels** (**Required**, list): List of light channels to be configured. First one will control channel `0x01` and the second one will control channel `0x02`.
- **uart_id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID of the UART component.

For each channel, you can have:
  
- **min_value** (*Optional*, integer): Minimum brightness, lamp will be turned off below this value.
- **max_value** (*Optional*, integer): Maximum brightness will be limited to this value when setting light to max.
- All other options from [Light](/components/light#config-light).

> [!TIP]
> Use `light.dim_relative` [Action](/components/light#lightdim_relative-action) to implement dim up/down with long-press:
> 
> ```yaml
> # Example for long press dimming
> binary_sensor:
>     ...
>     on_multi_click:
>       - timing:
>           - ON for at most 0.5s
>         then:
>           - logger.log: "Short press"
>           - light.toggle: dimmer1
>       - timing:
>           - ON for at least 0.7s
>         then:
>           - logger.log: "Long press"
>           - while:
>               condition:
>                 binary_sensor.is_on: terminal_s1
>               then:
>                 - light.dim_relative:
>                     id: dimmer1
>                     relative_brightness: 5%
>                     transition_length: 0.1s
>                 - delay: 0.1s
> ```

## Technical details

The device is using Tuya-compatible application structure with two main components:

- a [Tuya CB3S](https://developer.tuya.com/en/docs/iot/cb3s?id=Kai94mec0s076) module, used as an application-level processor,
  wifi, Tuya comms, etc, (this will be replaced with our custorm firmware),
- secondary, application-specific MCU responsible for controlling triac at strictly defined moments.

> [!NOTE]
> CB3S module is using a Beken BK7321N microcontroller. The support for that family of products is added to ESPHome with
> the use of [LibreTiny Platform](/components/libretiny).

Unlike other Tuya-based dimming devices:

- external switch input is connected to CB3S module instead of the second MCU,
- communication to dimming MCU is unidirectional (uses ony TX pin of the UART interface),
- the protocol is different than in other [Tuya](/components/light/tuya) devices.

There is no confirmation from MCU whether the light has actually switched-on, nor it is any information about overheating or
unexpected events - just fire the command over UART and "hope that it works".

The UART needs only `tx_pin`, which is usually `GPIO11` on these devices. The physical switches connect to `GPIO08` for CH1
and `GPIO09` for CH2.

### The control protocol

The protocol to control brightness is very simple and each frame consists of:

| Zero | Zero | Syn  | Head | Update | Channel1 | Channel2 | Foot | Foot | Foot | Zero | Zero |
|------|------|------|------|--------|----------|----------|------|------|------|------|------|
| 0x00 | 0x00 | 0xff | 0x55 | `<UU>` | `<XX>`   | `<YY>`   | 0x05 | 0xdc | 0x0a | 0x00 | 0x00 |

where:

- `<UU>` is the Channel ID being updated by the given command (either `0x01` or `0x02`)
- `<XX>` is brightness value for Channel 1
- `<YY>` is brightness value for Channel 2

with brightness values ranging between `0x00` - `0xff`.

The protocol also works with different numer of leading/trailing zeroes - this hasn't yet been reverse engineered. There's
no confirmation, no acks, no feedback.
