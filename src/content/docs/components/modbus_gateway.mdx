The `modbus_gateway` component lets several Modbus masters share one RTU bus. One request is on the bus at a
time, and the response goes back only to the port that sent it. The gateway does not poll. The masters do.

Set up the [UART buses](/components/uart/) first. One bus is the server. Each other bus is a master. A port
can instead be a UART this component creates. Use that id as the `uart_id` of a [Modbus](/components/modbus/)
hub. A [Modbus Controller](/components/modbus_controller/) then uses the hub like any other bus.

```yaml
# Example configuration entry
modbus_gateway:
  - uart_id: bms_bus
    ports:
      - uart_id: inverter_bus
      - id: local_bus

modbus:
  - uart_id: local_bus
```

## Configuration Variables

- **id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID used for code generation.
- **uart_id** (**Required**, [ID](/guides/configuration-types#id)): The [UART bus](/components/uart/) the server
  is connected to. No other component reads or writes this bus.
- **response_timeout** (*Optional*, [Time](/guides/configuration-types#time)): How long to wait for a response
  before the next port may use the bus. Defaults to `500ms`.
- **ports** (**Required**, list): The masters. At least 1 and at most 4. See [Ports](#ports).

## Ports

Set `uart_id` or `id`, not both.

- **uart_id** ([ID](/guides/configuration-types#id)): A [UART bus](/components/uart/) a master is connected to.
  Requests are read from it and the response is written back. A UART can be listed once, and it cannot be the
  server bus.
- **id** ([ID](/guides/configuration-types#id)): Creates a UART. Use it as `uart_id` of a
  [Modbus](/components/modbus/) hub, not the server bus. The new UART copies baud rate, data bits, parity and
  stop bits from the server bus. Those settings are documented on the [UART bus](/components/uart/).

A port that sends again before it is served keeps the latest frame.
