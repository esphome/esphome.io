This component allows bytes to be transferred between a hardware [UART bus](/components/uart/) and a TCP socket.
Data is copied unchanged in both directions.

The component can connect to a remote host (`role: client`) or listen for one incoming connection (`role: server`).
Only one TCP connection is open at a time. When `role` is `server`, a new client is accepted only after the current
connection is closed.

> [!NOTE]
> The connection is plain TCP without encryption or authentication, so only use it on a trusted network.
> While no connection is open, bytes from the UART are discarded; a fast peer is throttled by TCP flow
> control instead of blocking the device.

> [!NOTE]
> Baud rate, data bits, parity and stop bits are set on the UART bus. They are not options of this component.

## Client

```yaml
# Example configuration entry
uart:
  - id: uart_bus
    tx_pin: GPIO17
    rx_pin: GPIO16
    baud_rate: 9600

uart_tcp:
  - id: uart_tcp_1
    uart_id: uart_bus
    host: 192.0.2.20
    port: 8899
```

## Server

```yaml
# Example configuration entry
uart:
  - id: uart_bus
    tx_pin: GPIO17
    rx_pin: GPIO16
    baud_rate: 9600

uart_tcp:
  - id: uart_tcp_1
    uart_id: uart_bus
    role: server
    port: 8899
```

This is not Modbus TCP. The bytes on the socket are the UART bytes, unchanged.

## Configuration variables

- **id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID used for code generation.
- **uart_id** (**Required**, [ID](/guides/configuration-types#id)): The [UART bus](/components/uart/) to use.
- **role** (*Optional*, string): `client` or `server`. Defaults to `client`.
- **host** (**Required** when `role` is `client`, string): The host to connect to. An IP address or a hostname.
  This option cannot be used when `role` is `server`.
- **port** (**Required**, int): The TCP port to connect to, or to listen on.
- **reconnect_interval** (*Optional*, [Time](/guides/configuration-types#time)): The time to wait before trying
  again after a failure. Defaults to `5s`.
- **connected** (*Optional*): A binary sensor that reports whether the TCP connection is established. All options
  from [Binary Sensor](/components/binary_sensor#config-binary_sensor) are supported.

## Zigbee coordinator

Zigbee2MQTT can use a server of this component instead of a serial port on the machine that runs it.
In its `configuration.yaml`, set `serial.port` to `tcp://192.0.2.20:6638` and `baudrate` to the same value
as the UART below. `adapter` is `zstack`, `ember`, `deconz`, `zigate` or `zboss`, depending on the stick.
Zigbee2MQTT is the one TCP client. This setup has not been tested with this component.

An ESP32 with USB host, such as the ESP32-P4, can host the stick through [USB Host UART](/components/usb_uart/).
The stick's USB-serial chip must be one of the types listed there. A Sonoff Dongle-E is a CP2102 (`cp210x`).
A Sonoff Dongle-P is a CH340 (`ch340`). The board has to power the stick.

> [!NOTE]
> Use [Ethernet](/components/ethernet/). A coordinator drops bytes more easily on Wi-Fi than on a cable, and
> Zigbee2MQTT does not tolerate that. If Wi-Fi is the only network, do not also enable `bluetooth_proxy`,
> `esp32_ble_tracker` or `esp32_ble` on this device. They share the radio with Wi-Fi.

```yaml
# Example configuration entry
usb_uart:
  - type: cp210x
    channels:
      - id: zigbee_stick
        baud_rate: 115200

uart_tcp:
  - uart_id: zigbee_stick
    role: server
    port: 6638
```
